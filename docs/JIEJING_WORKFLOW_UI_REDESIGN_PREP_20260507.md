# 捷境工作流界面大调整准备方案 2026-05-07

这份文档用于明天重做工作流界面时对齐方向。它是内部产品备忘，不改现有页面，不代表已经接入真实 eBay API、真实 1688 API、真实支付或生产 Hermes。

## 1. 不偏离的主线

捷境不是代运营承诺工具，也不是单纯的聊天机器人。当前产品主旨是：

- 帮 eBay 卖家省掉重复、复杂、容易出错的经营流程。
- AI CEO 接收商家目标，拆成可执行任务，后台岗位处理细节，前台只给商家看结果、缺口、风险和需要确认的动作。
- 能帮助商家提高流程质量和判断清晰度，但不承诺订单、利润或店铺一定做起来。
- 官网只介绍价值；登录、身份选择、向导、工作流、API 连接、铺货和客服物流必须在登录后。

## 2. 外部平台可借鉴的做法

### Shopify Flow

Shopify Flow 的核心是 trigger / condition / action。它适合高级商家配置自动化，但不适合小白一进来就自己搭流程。

捷境吸收方式：

- 小白不看触发器和条件，只看“AI CEO 已经把流程推进到哪一步”。
- 高级用户以后可以在设置里调整触发条件、默认规则和审批边界。
- 预设模板比自由搭建更重要，例如“从货源图到 Listing 草稿”“订单催发货处理”“客服退款风险拦截”。

参考：https://help.shopify.com/en/manual/shopify-flow

### ShipStation

ShipStation 强在订单状态、筛选、标签、批量处理、物流规则和自动化规则。它不是先讲 AI，而是先让商家快速知道订单卡在哪里。

捷境吸收方式：

- 客服与物流页必须以订单状态为中心：待回复、待发货、tracking 异常、退款风险、承诺风险。
- 搜索框必须突出：订单号、买家、SKU、tracking 都能搜。
- 自动化规则应服务于“少点重复操作”，例如自动生成回复草稿、识别超时风险、提醒补 tracking。

参考：https://help.shipstation.com/

### Zapier / Make / n8n

这些平台的强项是可视化流程、节点、分支、执行日志和失败重跑。但对电商小白来说，节点图太像工程工具。

捷境吸收方式：

- 后台可以是节点和执行日志，前台不要让商家管理复杂节点。
- 工作流界面应展示“阶段卡 + 当前状态 + 输出 + 下一步”，不是大面积流程连线。
- AI 工作记录要像执行日志，但用商家能看懂的话：检查了什么、用了什么资料、结论是什么、缺什么、下一步能不能自动推进。

参考：https://n8n.io/

### eBay 官方链路

eBay Listing 不是一个标题就能发布。正式接入时需要走 OAuth 授权，并围绕类目、Item specifics、库存、Offer、付款/发货/退货政策、发布、订单履约等 API/规则组织。

捷境吸收方式：

- 工作流必须按 eBay 真实链路设计：商品输入 -> 市场判断 -> 货源/履约 -> 类目与 Item specifics -> Listing 草稿 -> 素材 -> 费用利润 -> 风险与确认 -> 发布后订单/客服/物流。
- 只读授权优先；发布、改价、改库存、广告、退款、买家承诺、采购付款和地址写入必须确认。
- 读取 Listing/订单/费用/广告表现，是为了减少手工复制、预填资料、做费用复盘、识别重复流程，不是为了承诺“帮店铺诊断为什么没订单”。

参考：
- https://developer.ebay.com/develop/guides-v2/authorization
- https://developer.ebay.com/api-docs/sell/inventory/overview.html
- https://developer.ebay.com/api-docs/sell/account/overview.html
- https://developer.ebay.com/api-docs/sell/fulfillment/overview.html
- https://developer.ebay.com/api-docs/commerce/taxonomy/overview.html

### eBay 工具与跨境工具

AutoDS、3Dsellers、inkFrog、ZIK Analytics 这类工具常见能力是选品、竞品分析、Listing 管理、库存/价格监控、客服、订单履约和批量处理。

捷境不能照搬“工具堆功能”，要变成：

- AI CEO 做统一入口。
- 选品、上架、素材、客服、履约、费用、风控都归到同一个项目里。
- 每个模块都要有工作记录和确认边界。
- 小白先跑通一件商品，老卖家再做批量和多店铺。

参考：
- https://www.autods.com/
- https://www.3dsellers.com/
- https://www.inkfrog.com/
- https://www.zikanalytics.com/

## 3. Hermes 底座如何映射到前台

Hermes 内部可以有 CEO、市场、产品、客服、财务供应链、风控、工程等岗位。前台不要堆很多经理名字。

前台建议映射成 7 个商家能理解的模块：

1. 机会判断：这个品是否值得继续。
2. 货源与履约：采购价、供应商、发货地、重量、时效、退货边界。
3. 上架资料：标题、类目、Item specifics、描述、价格、库存、政策。
4. 素材工坊：主图、场景图、详情图、尺寸图、视频和口播脚本。
5. 费用利润：平台费、广告、物流、退款预留、最低利润线。
6. 客服与售后：产品档案、FAQ、话术边界、退款/重发/承诺风险。
7. 确认中心：发布、钱、广告、退款、买家承诺、平台授权、采购付款。

内部岗位输出统一变成：

- 已检查：这一步做了什么。
- 使用资料：商家提供 / 官方 API / 公开数据 / 演示数据 / AI 推断。
- 结论：能不能继续，为什么。
- 缺口：还缺什么资料。
- 可自动推进：低风险草稿、预填、分类、报告。
- 需确认：影响钱、平台写入、退款、广告、承诺、授权、采购的动作。

## 4. 明天工作流界面建议结构

### A. 顶部状态栏

展示当前店铺、当前项目、阶段、API 状态、自动化权限和待确认数量。

例：

- 店铺：eBay US 店铺 A
- 项目：倒流香炉 Listing
- API：eBay 只读已接 / 1688 未接
- 权限：草稿自动，发布与资金确认
- 待确认：2 项

### B. 左侧导航

建议保留：

- AI CEO 工作舱
- 选品 / 上架项目
- AI 工作记录
- 确认中心
- 客服与物流
- 铺货工厂
- 设置与账户

铺货工厂不要给小白一开始太突出。只有当用户选择已有店铺、多店铺、或完成至少一个商品闭环后，才强调批量。

### C. 主工作区

不要做成复杂后台。建议用“项目推进板”：

- 左栏：项目列表 / 当前商品 / 搜索。
- 中间：阶段卡片，按真实 eBay 顺序排列。
- 右栏：AI CEO 当前结论、下一步、待确认。

每张阶段卡必须固定回答四件事：

- AI 已处理什么。
- 当前产出是什么。
- 缺什么资料。
- 下一步自动推进还是需要确认。

### D. AI CEO 聊天区

聊天不应该占满整个工作流。它是入口，不是全部。

建议：

- 在 AI CEO 工作舱里保留大聊天框。
- 在选品/上架项目页，把聊天变成右侧窄栏或顶部输入条。
- 商家发图片、链接、需求时，AI CEO 自动创建项目并把输出分发到阶段卡。

### E. AI 工作记录

工作记录要像“可读的执行日志 + 汇报预览”：

- 左侧是记录列表，按项目和模块筛选。
- 右侧是报告预览，可滚动。
- 点击记录卡直接切换预览，不再多一个“预览汇报”按钮。
- PDF 是可选导出，不是默认阅读方式。

### F. 确认中心

确认中心要更简单，只分 5 类：

- 发布与平台写入。
- 资金与采购。
- 退款与售后。
- 广告与预算。
- 买家承诺与账号安全。

卡片文案不要像法律文件。每张确认卡只说：

- 这是什么动作。
- 为什么需要你确认。
- 不确认会怎样。
- 默认以后是否按同类规则执行。

## 5. 四个身份的工作流入口

### 小白起步

目标：让不会开店的人少走弯路，先跑通第一件商品闭环。

推荐步骤：

1. 账号状态：是否已有 eBay 卖家账号。
2. eBay 官方授权解释：API 是官方软件通道，不是交账号密码。
3. 只读授权或跳过：推荐只读，不信任可先跳过。
4. 货源输入方式：图片、链接、表格、自己描述，或绑定 1688 读取。
5. 履约方式：供应商直发、国内中转、海外仓、自发货。
6. 费用口径：采购价、重量、物流、平台费、退货预留。
7. Listing 必填项：类目、Item specifics、标题、图片、政策。
8. 素材方式：上传图重做，或完全由 AI 出图和脚本。
9. 客服学习：商品档案、FAQ、物流承诺、退货口径。
10. 权限确认：发布、资金、广告、退款、买家承诺必须停住。

### 已有店铺接入

目标：不是诊断为什么没订单，而是把现有店铺的重复流程接进捷境。

推荐步骤：

1. eBay 店铺 API 接入方式：官方只读授权 / 样本导入。
2. 读取范围：Listing、订单、费用、广告表现、业务政策、账号状态。
3. 先自动化哪块：Listing 草稿优化、费用核算、客服物流、素材补齐、订单处理，可多选。
4. 费用口径：平台费、广告、物流、退款预留、采购价，必须多选或默认全选。
5. 现有业务政策检查：付款、发货、退货、handling time、item location。
6. 客服学习：从现有 Listing、订单、FAQ 学习商品档案。
7. 权限边界：哪些动作只生成草稿，哪些需要确认。
8. 第一条改造项目：选择一个 Listing 或一个订单场景先跑通。
9. 进入工作舱：生成项目推进板和工作记录。

### 已有订单处理

目标：先保护订单履约、客服和退款风险，让商家少漏处理。

推荐步骤：

1. eBay 订单读取：只读授权或导入最近 7/30 天订单。
2. 订单优先级：待发货、买家催单、tracking 异常、退款风险、差评风险。
3. 物流方式：平台物流、橙联、海外仓、供应商直发、自发货。
4. 客服权限：低风险自动草稿/自动发送，高风险停住。
5. 售后边界：退款、重发、补偿、承诺到货日必须确认。
6. 费用复盘：每单采购、运费、平台费、退款预留。
7. 默认处理规则：同类催发货、tracking 更新、已妥投说明可默认。
8. 进入客服与物流工作台。

### 多店铺管理

目标：统一规则，分店铺执行，避免串店、串权限、串成本。

推荐步骤：

1. 店铺结构：几个 eBay 店铺、国家站点、团队成员。
2. API 接入：逐店只读授权，或先用样本。
3. 权限模型：谁能看、谁能编辑、谁能确认发布/退款/广告/采购。
4. 店铺规则：发货地、handling time、退货地址、币种、税费、利润线。
5. 模板共享：标题模板、描述模板、素材模板、客服口吻、政策模板。
6. 批量铺货边界：一键生成草稿可以，批量发布必须确认。
7. 异常队列：跨店订单、库存、价格、退款、广告预算。
8. 报告口径：按店铺、品类、项目、人员、费用汇总。
9. 进入多店铺控制台。

## 6. 明天优先级

第一优先级：

- 重做工作流主界面为“项目推进板”，不要堆聊天和经理卡。
- AI 工作记录改成点击即预览、右侧滚动报告。
- 确认中心减法，只保留高风险核心确认。
- 客服与物流以订单状态和搜索为中心。

第二优先级：

- 四个身份向导再打磨成独立产品流程。
- 设置与账户补齐 eBay API、1688/货源 API、物流接口、客服权限和默认规则。
- 铺货工厂改成更直观：导入货源池 -> AI 评分 -> 批量生成草稿 -> 抽检 -> 分批确认。

第三优先级：

- 移动端只保留最重要动作：AI CEO、确认中心、订单异常、工作记录预览。
- 高级规则和批量操作在桌面端更完整，手机端主要做查看和确认。

## 7. 更强的产品建议

### 7.1 工作流不要叫“流程图”，要叫“经营队列”

商家每天关心的不是流程长什么样，而是：

- 现在有哪件事卡住。
- AI 已经替我做完了什么。
- 还缺我补什么。
- 哪个动作会影响钱、账号、买家承诺。
- 点确认以后会发生什么。

所以明天的核心界面建议叫“经营队列”或“项目推进”，而不是“工作流图”。后台可以有节点、分支和执行日志，前台应该是任务队列、阶段卡、确认卡和报告预览。

### 7.2 AI CEO 工作舱应该分成三层

第一层：AI CEO 输入区。

商家只需要说目标、发图片、发链接、发订单号。不要让商家先选很多模块。

第二层：当前项目推进区。

AI CEO 把输入自动转成项目，例如“旅行压缩收纳袋 Listing 项目”“倒流香炉素材重做项目”“订单延迟客服项目”。

第三层：后台处理结果。

不要堆很多经理卡。用商家语言显示：

- 市场与机会
- 上架资料
- 素材输出
- 费用利润
- 履约客服
- 风险确认

### 7.3 每个项目卡必须有“下一步”

现在很多 SaaS 的问题是页面很好看，但用户不知道下一步点哪里。捷境要反过来：

- 每个项目卡只突出一个主按钮。
- 如果低风险，就写“继续自动生成草稿”。
- 如果缺资料，就写“补充重量/尺寸/采购价”。
- 如果高风险，就写“去确认中心”。
- 如果已完成，就写“查看汇报 / 复制上架资料 / 生成下一批”。

### 7.4 用“自动化等级”代替复杂权限说明

商家不应该反复理解权限术语。建议把权限做成 4 档：

1. 观察模式：只读取、整理、生成报告，不改平台。
2. 草稿模式：自动生成 Listing、素材、客服、采购单草稿。
3. 半自动模式：低风险动作按默认规则执行，高风险进确认中心。
4. 托管规则模式：按商家设定阈值执行，超过金额、发布、退款、广告、买家承诺仍确认。

这比一句一句解释“钱、发布、退款、广告、客服”更产品化，也更容易被用户理解。

### 7.5 让 API 接入变成“省事程度”的选择

API 不要只写成技术连接。建议每个接口都说明“接了以后省掉什么”：

- eBay 只读授权：少复制 Listing、订单、费用、广告表现和店铺政策。
- eBay 写入权限：发布、改价、库存等只能在确认后执行。
- 1688/货源读取：少复制商品规格、价格、库存、发货地和供应商资料。
- 采购下单接口：真实下单、付款、地址写入必须确认。
- 物流接口：少查 tracking、少手填发货状态、自动识别异常。

这样商家不会觉得“你在要我的权限”，而是知道“我授权以后具体少做哪一步”。

### 7.6 铺货工厂必须从“批量按钮”改成“批量前质检”

批量铺货不是一键越多越好。捷境如果想高级，需要先建立一套批量前质检：

1. 货源池：导入图片、链接、表格、API 商品。
2. AI 初筛：去掉侵权风险、低利润、发货不稳、素材不足、规格不清的品。
3. 分组：同类目、同供应商、同履约方式、同素材模板。
4. 批量生成草稿：标题、类目、Item specifics、图片需求、价格、物流承诺。
5. 抽检：每组抽几条给商家看，不是 100 条一起砸过来。
6. 分批确认：每批确认后再发布或保存草稿。
7. 发布后监控：价格、库存、订单、差评、退款和物流异常回流。

这会让捷境看起来不是普通铺货工具，而是更稳的 AI 批量经营系统。

### 7.7 客服不是单独聊天，必须先吃到商品档案

客服自动化之前，必须先有产品档案：

- 商品是什么。
- 材质、尺寸、包装、配件、是否含赠品。
- 物流时效、发货地、退货口径。
- Listing 里承诺了什么。
- 常见问题怎么答。
- 哪些话不能说，例如保证到货、承认缺陷、直接承诺退款。

所以客服与物流页要显示“客服已学习的商品档案”。没有商品档案时，只能生成保守草稿，不能自动发送。

### 7.8 工作记录要从“日志”升级为“AI 工作汇报”

工作记录不是流水账。建议每条记录都像一个小报告：

- 结论先行。
- 数据来源标清楚：商家提供 / 官方接口 / 公开信息 / 演示数据 / AI 推断。
- 缺口单独列。
- 下一步单独列。
- 风险和确认单独列。

这会建立信任，也能让用户愿意付费，因为他看到 AI 不是在聊天，而是在替他做经营整理。

### 7.9 移动端只做三件事

手机上不要完整后台。移动端建议只保留：

- 看 AI CEO 汇总。
- 批准/驳回确认事项。
- 查看订单异常和客服风险。

素材工坊、批量铺货、规则配置和复杂报告主要放桌面端。

### 7.10 明天 UI 的核心画面建议

第一屏：

- 左侧：店铺/项目切换。
- 中间：当前项目推进板。
- 右侧：AI CEO 当前建议和下一步。

- AI 工作汇报预览。

第四屏：

- 客服与物流。
- 顶部搜索订单，中间订单队列，右侧客服草稿和物流状态。

第五屏：

- 设置与接口。
- eBay、1688/货源、物流、客服权限、默认规则都放这里。
