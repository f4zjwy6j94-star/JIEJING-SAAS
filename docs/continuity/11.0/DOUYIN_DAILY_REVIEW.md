2. 使用本机Chrome，先识别连接及账号；不写死浏览器/标签ID。只读新捷境作品，不翻旧私密内容；识别实际作品ID、标题、发布时间和公开/审核状态。
3. 优先查看作品状态与异常详情。平台有流量减少/需优化等明确提示时先留证，区分作品级与账号级；不靠改话题、付费投流或重发试图绕过。
4. 记录可见曝光、播放、观看时长、完播/2秒跳出、赞评藏转、吸粉、主页访问及各流量来源，同时记录观察时刻、后台截止时刻、统计窗口、实际作品年龄。`-`、未开放、未出数为未知，不作0。
5. 不将矛盾数字强行拼成漏斗。零/未知播放分母下的百分比只保留平台原显示值，暂不做有效表现判断；来源缺失不凭经验补数。
6. 在每日运行中，为作品记录首次达到24小时和72小时后的可用快照，注明实际年龄；例如发布后25小时获取，就写25小时，不冒充精确24小时。区分作品累计值和两个快照差值；口径变化不计算差值。
7. 对照相近时长、同龄且状态正常的作品分析，写三栏：已证实事实、待验证原因、下一条改一件什么。数据少或受限制时降低因果结论，不照抄固定爆款阈值。
8. 第7天起每周汇总选题/开头/形式与有效咨询，选择2–3个有证据支持的主题延展；没有数据就明确缺测，不虚构周报成绩。
9. 用已有`performance.template.json`口径，仅保存汇总及安全引用。有效咨询、体验、收费只在归因可验证且访问获准时记录；不为复盘读取付款/客户明细或加埋点。
10. 更新待制作脚本与复盘建议、当前执行摘要；验证JSON/引用/固定源码SHA并通过WORK_SYNC save显式路径交回现有分支。媒体/截图/原始日志不上传。无法安全保存时保留D盘独立回执并如实报告。

## 从事实到改进

| 观察 | 应做的诊断/改进 | 不作出的推论/动作 |
|---|---|---|
| 流量减少或需优化 | 读通知，保留作品与输入材料；对照具体规则排查原创性、信息完整性、重复广告表达 | 不默认删片重传，不宣称“换标签就恢复” |
| 正常状态但播放很少 | 先核对观察时长、公开可见及数据更新范围，再测试更具体的经营问题 | 不凭低播放认定账号废了或必须买流量 |
| 有可解释的观看样本，开头流失明显 | 下一条只优先改前三秒：可见问题/结果和真实操作证据 | 不同时乱改标题、时长、声音、标签后声称找到原因 |
| 观看尚可却无经营咨询 | 核对目标人群、使用场景和单一行动提示 | 不把泛AI点赞等同卖家需求或收入 |
| 有真实体验但无付费 | 检查内容承诺与实际体验的匹配；需要业务排查时另走授权范围 | 不擅自改收费、优惠、退款或用户权益 |
