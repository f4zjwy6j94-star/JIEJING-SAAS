## 开工：先接收，再读进度

从实际源码根目录运行（Windows 用可用的 `python`，云端用 `python3`）：

```text
python docs/continuity/11.0/work_sync.py status --repo .
python docs/continuity/11.0/work_sync.py receive --repo .
```

`status` 只读检查身份、分支、工作树和远端。`receive` 只接受正确仓库/分支、干净工作树下的正常 fetch 与 fast-forward；不会切换分支、stash、reset、clean 或处理冲突。失败就保留现场并说明原因，不能声称“已经最新”。首次接入仍在旧分支的 10.0 应先按已授权的保全流程保存原 7 份文档，无损完成分支对齐，再使用本入口。

接收成功后完整读执行索引的当前接续摘要。最少核对：当前目标、负责端、最近完成事项、经营者最新决定、验证结果、下一步及阻塞项。旧段落仅追溯，不重复已经完成或取消的工作。需要历史细节时查现有私有索引；摘要不是完整聊天镜像。

## 推进后：先更新记录，再保存

重要步骤完成、经营者改变方向，或工作发生变化后准备切端/结束任务时，由执行端主动更新当前执行索引。说明已做什么、哪些没做、真实成果路径、校验退出码、下一步和负责端。随后审看本任务文件差异并做必要验证，以明确的相对路径调用：

```text
python docs/continuity/11.0/work_sync.py save --repo . --message "docs: save current work handoff" --path docs/JIEJING_CURRENT_EXECUTION_STATE.md --path docs/continuity/11.0/WORK_SYNC.md
```

上例仅演示参数；必须替换为本次实际改动，不能照抄后提交未审查文件。保存必须包含实际更新的执行索引。脚本拒绝已有暂存内容、未列出的改动和受保护的素材/秘密/数据库等路径，复用既有秘密扫描，再正常提交、推送并读回远端。它不会写项目进度、自动改断言、重跑全门禁或扩大权限；内容判断仍由当前任务负责。

`--output` 可写安全 JSON 回执，必须是仓库外的全新文件；不覆盖旧回执。stdout 同样提供 JSON。推送或读回失败时保留本地提交/文件并记录实际错误，不能强推、自动重基或声称已保存到另一端。

提交或推送超时可能已经在 Git 端生效；回执中的成功布尔为 false 只表示未确认，不能当作“绝对未写入”。先只读检查实际 HEAD 和远端，再决定如何恢复，不重复盲推。

执行索引等部分文件另被 `CHECKPOINT.safe.json` 的 `pinned_files.repo` 固定。合法修改这些文件时，审查后同步更新对应源码 SHA，并将该清单纳入本次明确路径；不改未变文件的固定值，不更新历史素材 SHA 来掩盖损坏，不删完整性断言。保留仓库约定的文本行尾；Windows CRLF 导致的全量复原差异要另行报告，不把 Git 接续成功扩大为所有原始字节一致。脚本不会自动重写这份完整性清单。

## 双方如何交接

- 保存端的远端 SHA 读回一致，只说明已交出到共同分支；另一端离线时是“等待接收”。
- 接收端 `receive` 成功后，本地 HEAD 与远端 SHA 一致，才说明该端已收到。其回执还需列出实际路径、工作树状态与当前下一步。
- 同一项任务一次由一端推进，交出后停止继续修改该任务。执行索引中的负责端是协作约定，不是强制锁。若同时推进不同任务造成远端变化，先保留双方、核对后合并，禁止覆盖或自动重做对外动作。
- 电脑突然关闭只能继续最后成功保存的内容；不会读取关机电脑上的未提交修改或登录态。开始一次本机操作前必须由本地工具实际验证可用，不因云端在线就说能接管桌面。

## 验收范围与当前限制

`PROJECT_SYNC_MANIFEST.safe.json` 配合原 `hybrid_check.py`，只核对本轮源码 Git 身份；`work_sync.py` 负责正常接收/保存。原 `HYBRID_MANIFEST.safe.json` 仍保留 v10 ZIP 的严格条件，原 `verify_checkpoint.py` 仍保留全部资料断言，没有为了本轮改变其门槛。

这个流程是“每次推进保存、另一端开工接收”，没有安装后台同步程序、计划任务或 Git hooks。两条聊天不会自动合并，开关机不会自动把执行到一半的任务迁移。完整聊天记忆、所有本地原始材料和浏览器身份不在此同步范围。

新脚本的临时仓库测试不能代替真实 Windows 验收。实际双向验收需要：云端保存并读回 → 本地接收并核验 → 本地记录一条非敏感接收结果并保存 → 云端接收并核验。只有对应真实回执齐全才标记双向通过；云端单方面完成不冒充本地已接入。源/进度接续成功也不是生产部署、环境发布、视频发片或新任务冷启动通过。
