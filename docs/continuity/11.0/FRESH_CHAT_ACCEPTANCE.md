# 新云端对话接续验收

本文件是已准备的验收方法，不是新对话已启动或通过的回执。先验证云端新任务；本地Windows新对话另验。保留原10.0/11.0，本任务不需要先把旧聊天移入客户端项目页面，也不要求启用Your dot。

## 经营者在客户端进行的操作

1. 在现有私有云环境的设置审核、保存并发布已准备的最新配置；若该版本已发布则无需重复。发布的是开发工作环境，不是捷境网站。准确草稿/提交看最新安全保存回执，不固定复原为旧迁移提交。
2. 新建一条Codex云端任务，在“Work in / 工作位置”选择Cloud及既有“捷境10.0·开发与视频·私有”环境。不要Base Environment、新仓库或worktree。
3. 发下面短指令。无需复制旧聊天或先告知全部项目状态。

```text
请接续捷境项目，本轮只做新对话恢复验收。
请按项目已有接续规则，实际检查版本、接收最新记录并读取当前进度。
报告当前目标、最近完成事项、已暂停事项和未完成项，并列出实际读取的文件及校验结果。
核对历史资料入口是否可用；缺失就明确报告，不凭摘要补全。
只保存安全验收记录，不修改业务代码、不部署、不制作或发布视频、不重跑全部SaaS测试。
```

## 接手助手执行要求

- 先确认实际环境和 `/workspace/JIEJING-SAAS` 存在；缺失先按环境说明/路径映射定位，不能初始化替代仓库。读取AGENTS.md与WORK_SYNC.md。正确分支且干净时用既有 `work_sync.py status/receive` 接收；dirty、分叉、错分支按原规则保留现场报告。
- 读取最新执行索引的“当前接续摘要”，历史只按需追溯。报告自己的实际源码路径、完整HEAD、分支、dirty、远端SHA、当前目标、最近成果、暂停/取消事项、剩余项，引用实际文件。
- 用 `hybrid_check.py --repo . --manifest docs/continuity/11.0/PROJECT_SYNC_MANIFEST.safe.json --check-remote` 核对源码身份，保留退出码。该清单没有素材条目，不能据此证明历史/视频齐全。
- 检查 `/workspace/jiejing-continuity/10.0/START_HERE.md` 和其资料目录/回执能否读取；核实入口后按需抽查一个非敏感历史或映射条目，明确已测范围。只核对入口/抽查不能宣布全量历史已恢复；不重复全量SaaS门禁或视频生成。缺项报告，不删断言、不改旧素材清单。
- 写一份不含秘密、原始聊天正文或登录态的安全验收说明，记录本任务是经营者新建任务、实际工具结果及限制；工具未提供新任务/环境ID时不要编造。更新同一执行索引和实际变更文档的源码SHA，按WORK_SYNC显式路径save交回，读回远端。仅接收成功与写回成功分别报告。
- 视频下载/制作/发布、生产/拼嘚、OAuth、付款、COS额外备份、设备授权与Your dot启用均不属于此验收。

## 如何判定

证据要来自真正新建的Codex云端任务。当前11.0继续运行、内部子代理读取相同目录、脚本单独通过或草稿保存均不能代替这一步。

源码/进度接续通过需要：正确环境和仓库、实际安全接收/版本一致、实际读取并正确复述最新决定、明确历史/素材访问范围、保存安全结果并读回远端。原端再从共同分支收到结果并复核。失败必须列精确项，保留现场；不要用口头“全部记住”当通过。

本轮即使通过，结论也仅为新云端任务的源码/安全进度及已列明资料入口接续。它不证明完整聊天逐字共享、全部原始资料已云端化、Windows新任务、开关机自动转移、浏览器身份或生产部署通道通过。
