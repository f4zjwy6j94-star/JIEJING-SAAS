## 每次工作时如何接续

- 开始：检查实际 HEAD、分支、dirty、远端版本及本次所需资料。旧版本、缺文件或哈希不同必须明确报错；不无条件覆盖工作目录。
- 结束或准备关机：先保存获准改动、资料及最新任务状态；读回目标位置，再出交接回执。失败就标记未保存，不让下一端误以为最新。
- 同一任务由一端执行。发布、付款、部署等外部动作失联后先查结果，不能因租约过期或未看到回执就自动重做。同步授权不扩大这些动作的授权。
- 电脑开机、联网且桌面客户端可用时可以选择本地；电脑关闭后云端只能使用已实际迁入的文件和工具。本机 Chrome 不随关机迁到云端。

`hybrid_check.py` 是可移植的只读前置检查，配合 `HYBRID_MANIFEST.safe.json` 使用；它不会同步、fetch、修改工作文件、安装守护程序或接管任务。首次验收范围为 Git 身份与 v10 传输包，不能代替既有全量历史/素材验证器。本地 `--materials-root` 指向存放该 ZIP 的真实 Windows 目录，云端指向上述 v10 输出目录。

```text
python docs/continuity/11.0/hybrid_check.py --repo <实际仓库路径> --manifest docs/continuity/11.0/HYBRID_MANIFEST.safe.json --materials-root <v10 ZIP 所在目录> --check-remote
```
