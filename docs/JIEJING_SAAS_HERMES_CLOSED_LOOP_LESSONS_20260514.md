# 捷境 SaaS / Hermes 闭环测试经验同步

日期：2026-05-14  
来源：2026-05-13 理线夹全链路测试、SpeedPAK/橙联运费口径复核、素材工坊交付核查。

## 1. 本次结论

昨天的测试证明 Hermes 能按捷境 SaaS 的主链路跑通：

```text
AI CEO 接目标
-> 市场数据包
-> 市场经理报告
-> 财务/货源预审
-> CEO 价格与继续决策
-> 产品经理刊登资料
-> 素材任务包
-> 素材文件生成
-> 客服学习包
-> 财务履约终审
-> 独立确认中心
-> CEO 汇总
```

但测试也暴露出几个必须产品化的缺口。下面规则从今天起作为 Hermes 和 SaaS 的共同口径。

## 2. 素材工坊必须拆成两步

昨天 `05_asset_workshop.pdf` 实际是素材任务包，不是图片/视频文件。

以后必须分清：

| 状态 | 含义 | 是否可给商家看成成品 |
| --- | --- | --- |
| 素材任务包已生成 | 图片清单、prompt、尺寸、分镜、脚本、验证要求 | 否 |
| 素材生成中 | 系统正在生成 JPG/PNG/WEBP/MP4/WAV/SRT | 否 |
| 素材文件已生成 | 真实文件存在并有路径、尺寸、版本、状态 | 是，但仍可能需验证 |
| 素材验证通过 | 与实物/供应商事实一致，可进入发布前确认 | 是 |

SaaS 页面不能把“任务包”显示成“素材已生成”。Hermes CEO 也不能在汇报里混用。

## 3. 确认中心必须独立输出

昨天确认中心只是嵌在 CEO 报告里，不够产品级。

以后每个闭环必须有独立确认中心输出：

- 自动允许：只生成报告、草稿、问题清单、素材任务包。
- 一次默认：商家设过规则后可复用的低风险动作。
- 每次确认：发布 Listing、采购付款、退款、广告预算、改价改库存、政策修改、敏感客服承诺。
- 已阻断：资料不齐、利润不达标、类目未校验、物流报价未锁定、素材未验证。

真实发布按钮只能出现在确认中心，并且必须在阻断项解除后出现。

## 4. 财务预审必须在产品刊登前

昨天市场经理的价格建议和财务终审修正后的价格有偏差。产品经理如果提前拿市场粗估写刊登包，会把错误价格传下去。

新规则：

```text
市场报告 -> 财务/货源预审 -> CEO 价格裁决 -> 产品经理刊登资料
```

产品经理不得直接使用市场经理的粗估价格作为刊登价格。刊登资料必须使用 CEO / finance-supply 批准的价格区间。

财务预审至少包含：

- 采购价
- 国内运费或供应商运费
- 包装成本
- SpeedPAK / 物流报价状态
- eBay 费用
- 广告预留
- 退货/退款预留
- 店铺订阅/刊登费分摊
- 最低安全售价
- 红黄绿结论

## 5. 店铺配置要在 CEO 接目标阶段读取

昨天 `$18 flat rate` 运费策略发现太晚，导致市场报告、产品刊登和财务终审之间出现价格漂移。

新规则：CEO 接目标时先读取或要求用户补齐：

- fulfillment / shipping policy
- payment policy
- return policy
- 店铺订阅等级
- 可刊登额度
- item location / merchant location
- 默认处理时间
- 当前物流报价状态

如果店铺配置缺失，只能进入草稿，不得说“发布前已就绪”。

## 6. 物流报价必须分级

SpeedPAK/橙联运费不能再使用固定美元经验值作为发布级成本。

物流报价状态：

| 状态 | 用途 |
| --- | --- |
| 测试估算 | 演示、初筛，不可发布 |
| 官方公开价卡 | 参考计算，仍需账号价卡或 eDIS 确认 |
| 账号价卡 | 可用于发布前财务复核 |
| eDIS 实时报价 | 最接近真实扣费，可进入确认中心 |

如果运费变化会让利润低于安全线，系统必须自动回到财务复核。

## 7. 数据包和报告必须分开

市场经理不能边查边写长报告。

标准流程：

```text
market.data_packet -> market.report
```

数据包只负责事实和来源：

- eBay API 成功/失败
- 搜索引擎成功/失败
- 公开页面成功/失败
- 商家资料是否提供
- 1688 资料是否提供
- 价格样本
- 关键词样本
- 类目建议
- 数据缺口

市场报告负责判断：

- 是否值得继续
- 买家画像
- 竞品痛点
- 价格带
- 差异化机会
- 风险
- 下一步

## 8. 文件命名必须工程化

昨天出现过中文文件名跨 WSL/Windows/PDF 时乱码，以及 `05` 编号重复。

新规则：

- 系统文件名使用英文、数字、下划线。
- 中文只作为报告标题，不作为自动化消费的关键文件名。
- 每个阶段编号唯一。

建议编号：

```text
01_ceo_intake.md
02_market_data_packet.md
03_market_report.md
04_source_finance_precheck.md
05_listing_package.md
06_media_task_package.md
07_media_files_manifest.md
08_customer_service_learning.md
09_finance_final_review.md
10_confirmation_package.md
11_ceo_final_summary.md
12_repair_audit.md
```

## 9. 下游刷新规则

只要上游关键事实变化，下游必须标记 stale 并刷新：

- 财务改售价 -> 产品刊登要刷新。
- 运费改了 -> 利润、定价、客服时效承诺要刷新。
- 退货政策改了 -> Listing 描述和客服话术要刷新。
- 素材卖点变了 -> 客服 FAQ 和 Listing 卖点要刷新。
- 包装重量/尺寸变了 -> 运费、利润、物流政策要刷新。

SaaS UI 要显示：

```text
已过期，等待刷新
```

不能让商家拿旧报告继续确认。

## 10. 这次新增的产品化任务

| 优先级 | 任务 | 放在哪里 |
| --- | --- | --- |
| P0 | 独立确认中心输出 | Hermes CEO + SaaS 确认中心 |
| P0 | 财务预审前置产品刊登 | Hermes CEO + finance-supply + product-manager |
| P0 | 物流报价状态分级 | finance-supply + SaaS 财务卡 |
| P1 | 素材任务包/真实文件分离 | product-manager + SaaS 素材工坊 |
| P1 | 文件命名和编号规范 | CEO + team-repair |
| P1 | 下游 stale 刷新机制 | SaaS 后端任务状态 |
| P2 | 供应商问题模板按品类生成 | finance-supply + product-manager |

## 11. 对外产品口径

商家看到的是：

```text
AI CEO 接目标 -> 生成市场判断 -> 补齐货源和物流 -> 生成刊登草稿 -> 生成素材 -> 客服学习 -> 财务复核 -> 待我确认
```

商家不需要管理“市场经理、财务经理、产品经理”等后台岗位。后台岗位只在内部工作记录或高级报告里展示。

## 12. 当前边界

这份规则不代表已经接入真实生产发布。

仍然禁止绕过确认中心执行：

- 真实 eBay 发布
- 采购付款
- 退款/补偿
- 广告预算
- 改价/改库存
- 店铺政策修改
- 敏感客服承诺
