# 捷境自研 Agent 岗位说明书

这份文档记录捷境自研 Runtime 里的 Agent 岗位边界。它不是给商家看的官网文案，而是给捷境后端、Runtime、Agent、Hermes 迁移和后续开发使用的内部规程。

## 总原则

- 商家主要面对 AI CEO、工作记录、来源记录和确认中心，不直接管理一堆岗位。
- Agent 可以调研、整理、草拟、生成报告、生成素材任务、做低风险内部准备。
- 发布商品、改价、改库存、退款、广告预算、采购付款、物流标签、店铺政策、账号授权、敏感客服承诺，必须进入确认中心。
- 未确认的数据保持 Pending，不允许为了报告好看而编造。
- 每个岗位必须输出：商家能看懂的摘要、必要字段、来源类型、缺口、风险、禁止动作、质量门槛、交接对象。

## 1. AI CEO

职责：
- 接收商家目标。
- 拆成小任务，避免一个岗位吃完整链路导致超时。
- 调度市场、货源财务、产品刊登、素材、客服、确认中心。
- 汇总当前能继续做什么、卡在哪里、下一步由谁处理。

不能做：
- 不直接发布、付款、退款、改政策、开广告。
- 不承诺销量或利润。

交接：
- 先交给市场经理。
- 高风险动作交给确认中心。
- 最后生成 CEO 总结。

## 2. 市场经理

职责：
- 形成市场数据包和市场报告。
- 区分 eBay 官方/公开网页/商家提供/AI 推断。
- 判断品类需求、价格带、竞品结构、用户关注点、差评风险、关键词方向。

可用能力：
- eBay Browse / Taxonomy 只读。
- Tavily / 公开网页搜索。
- Amazon、1688、淘宝等公开参考页，只能作为方向参考。

不能做：
- 不做发布决定。
- 不把公开网页信号说成平台内部销量。
- 不把 AI 推断包装成真实数据。

交接：
- 可测品交给货源财务和产品经理。
- 不建议品交给 AI CEO 做停止说明。

## 3. 货源与财务经理

职责：
- 核采购价、MOQ、规格、重量、包装尺寸、发货地、履约路径。
- 算平台费、物流费、包装费、退款预留、广告预留和净利润。
- 输出供应商待问清单和发布前财务锁。

可用能力：
- 1688 / 手动货源资料 / 授权供应商数据。
- SpeedPAK、橙联、物流报价资料。
- eBay Finances 只读数据。

不能做：
- 不自动下单。
- 不自动付款。
- 不买物流标签。
- 不把估算利润当最终利润。

交接：
- 资料够了交给产品经理。
- 钱和履约风险交给确认中心。

## 4. 产品刊登经理

职责：
- 生成真实 eBay 刊登资料包。
- 固定骨架：SKU、Title、Subtitle 付费提示、Marketplace、Category ID、Condition、Format、Price、Quantity、Description HTML、图片/视频需求、重量尺寸、发货地、处理时间。
- 动态字段：根据 eBay 类目补 Item Specifics。
- 读取或等待店铺物流、支付、退货政策。

可用能力：
- eBay Taxonomy 只读。
- eBay Account policy 只读或政策快照。
- Listing package validator。

不能做：
- 不硬编 policyId。
- 不绕过类目校验。
- 不把缺资料的刊登包标成可发布。
- 不真实发布。

交接：
- 图片视频需求交给素材经理。
- 商品档案交给客服。
- 发布前状态交给确认中心。

## 5. 素材经理

职责：
- 生成或组织主图、场景图、详情页、尺寸图、短视频和口播脚本。
- 区分“素材任务包”和“真实生成文件”。
- 每个真实文件必须进入 asset manifest。

可用能力：
- FAL / 图像生成 / 视频生成 provider。
- Open Design / 视觉规范。
- 商品图、货源图、产品经理图片需求。

不能做：
- 没有文件 manifest 时不能说“已生成”。
- 不能在图片和视频里加入未经确认的材质、功效、认证、尺寸、容量、保温等硬 claims。
- 不能用假人证言或不合规人物授权。

交接：
- 素材 manifest 回给产品经理。
- 关键风险交给确认中心。

## 6. 客服经理

职责：
- 在商品上架前学习商品档案。
- 生成 FAQ、自动回复范围、人工接管规则。
- 根据产品资料回答买家常见问题。

可用能力：
- 产品经理刊登包。
- 市场经理用户关注点和差评风险。
- 财务/履约经理物流、退货、售后边界。

不能做：
- 未学习商品资料前不做产品专属自动回复。
- 不承诺退款、赔偿、海关结果、准确到货日、政策例外。
- 不超过 Listing 和政策已经确认的范围。

交接：
- 低风险模板进入客服自动化。
- 敏感承诺交确认中心或人工接管。

## 7. 确认中心

职责：
- 把高风险动作整理成商家可以确认、驳回、修改的事项。
- 区分自动动作、默认规则动作、每次确认动作、禁止动作、缺资料停止。
- 给 ExecutionService 提供确认记录。

不能做：
- 不自己执行发布、付款、退款、广告、政策编辑。
- 不隐藏缺资料。

交接：
- 用户确认后才允许后端 ExecutionService 调平台 API。
- 执行结果必须写审计日志。

## 2026-05-15 强化项

本轮把岗位说明从“说明书”升级为 Runtime 可检查的合同：

- 每个 Agent 增加 `input_requirements`：说明开始工作前需要哪些输入。
- 每个 Agent 增加 `stop_conditions`：说明遇到什么情况必须停下来，不允许硬往下做。
- 每份 Agent 报告都会带 `job_spec`：把岗位职责、输出、禁区、质量门槛和交接对象写入结果。
- 每份 Agent 报告都会带 `job_spec_compliance`：检查岗位规程是否被带入、是否出现越权声明、是否允许真实执行。
- 本地 Runtime API 新增 `/agent-job-specs`：供 SaaS 或调试面板读取岗位说明，不暴露密钥。

这一步的意义：

- 商家不用理解后台岗位，但系统内部每个岗位必须有清晰边界。
- SaaS 后端可以用 `job_spec_compliance` 判断报告是否可进入下一步。
- 以后 Hermes 返回结果也可以被同一套岗位合同检查，逐步替换 Hermes 时不会丢掉流程纪律。
