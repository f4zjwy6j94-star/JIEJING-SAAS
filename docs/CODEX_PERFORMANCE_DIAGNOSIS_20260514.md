# Codex 卡顿原因诊断与清理建议

生成日期：2026-05-14

本文档记录当前 Codex 越来越卡的本地原因和建议处理方式。

本次只做诊断和建议，没有删除文件。

---

## 1. 主要结论

Codex 变卡不是单一原因，而是几个因素叠加：

- 当前对话线程极长，上下文恢复和总结负担变重。
- `software-demo` 目录积累了大量截图、临时 PNG、视频和素材。
- 当前项目放在 OneDrive 和本地文档目录中，文件变动多时同步和索引会增加负担。
- WSL Hermes、飞书、Edge/Codex WebView 同时运行，占用内存。
- 演示页面资源变大，浏览器预览和截图验证更容易卡。

## 3. 建议处理顺序

### 3.1 立即有效，不影响项目

- 重启 Codex。
- 关闭不需要的浏览器标签。
- 暂停 OneDrive 同步 1-2 小时再继续高强度开发。
- 不在当前超长线程里继续无限扩展，必要时用文档和记忆交接到新线程。

### 3.2 安全清理

建议只清理或归档这些内容：

- 根目录 `tmp*.png`
- 根目录 `.tmp*.png`
- 旧的截图验证图
- 已经不用于页面的临时素材
- 重复备份包，只保留最新 2 份

不建议随便清理：

- `assets` 中被页面引用的正式素材。
- `app.js`、`styles.css`、`index.html`、`design-huashu.html`。
- `docs` 中的项目决策文档。
- Hermes 真实输出和 eBay 测试报告。

### 3.3 推荐归档方式

不要直接删除，先移动到：

```text
software-demo/artifacts/archive/tmp-screenshots-20260514/
```

这样页面不受影响，历史也能找回。

---

## 4. 后续自动化建议

可以做一个手动执行的清理脚本：

```text
tools/archive-demo-temp-assets.ps1
```

规则：

- 默认 dry-run，只显示会移动哪些文件。
- 加 `-Apply` 才真正移动。
- 只移动根目录 `tmp*.png` 和 `.tmp*.png`。
- 不碰 `assets`、`docs`、`app.js`、`styles.css`、`index.html`。
- 每次归档到带日期的目录。

---

## 5. 一句话

Codex 越来越卡，主要是超长对话、WSL Hermes 常驻、OneDrive 同步和大量演示截图素材叠加造成的；当前最安全的处理方式是先归档临时截图和旧备份，不直接删除核心文件。
