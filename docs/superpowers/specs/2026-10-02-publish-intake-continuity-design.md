# 发布前交付收口：发布表云保存与单一检查入口

用户要求直接解决上一轮明确的使用缺口，不再用百分比、重做商品或不断换范围代替结果。本文件落实已推荐且本轮要求执行的范围，不开启视觉重设计。

## 方案

沿用现有 Listing checkpoint 的租户/店铺/完整商品身份隔离、不可变版本、CAS 和 mutation 重试。在现有 JSON 回执增加可选 `publish_intake: {values, basis}`，两者只允许现有表单字符串字段。保存只保留输入，不授予事实、图片权利、AI生成或发布权限。原10项文案字段合同不变，旧客户端未提供发布表时后端保留之前发布表，不静默清空。

不采用新建平行商品实现或实时多人协同；不继续只用本机保存。现有数据库版本记录已能保存扩展JSON，不增加新表或改历史迁移。

前端输入继续先写本机，再自动保存云端；本机旧发布表提供显式保存入口迁入云端。云端回执到达才能显示已同步。断网保留待保存输入；相同mutation精确重试；更换账号/商品和迟到回包不污染当前表单。另一设备更新时保留双方版本，明确选择，不自动覆盖。来源变化仍使相关成本/物流失效，模拟数据继续阻断真实发布。

第4步以“检查发布资料”为起点，使用已存在的只读检查，不把检查等同创建确认或实际发布。统一上方检查状态与下方明细；确认单对应另一独立执行阶段，只有符合既有条件才能继续。高级库存/草稿/正式发布能力保留，不擅自删功能。

## 测试与终点

按真实接口增量RED→GREEN：发布字段及显式空值保存/恢复、旧客户端兼容、过量/越权/敏感字段拒绝、并发冲突、mutation幂等；浏览器验证干净第二设备、旧本机恢复、刷新、断网重试、项目/账号切换、迟到保存、新事实失效与既有文案保存不退化。对第4步验证未检查/检查中/模拟阻断/失败/已有执行确认的准确状态和下一步。

复用既有同源接口和回归工具，不调用真实模型、生图、OAuth、eBay写入、付款或退款。代码及局部门禁通过不称部署完成；本批正式部署仍需部署边界与同候选完整门禁。当前数据库续费、合法卖家账号、真实商品证据、独立商家使用与盈利验证是外部验收，不能由测试数据或修改开关替代。
