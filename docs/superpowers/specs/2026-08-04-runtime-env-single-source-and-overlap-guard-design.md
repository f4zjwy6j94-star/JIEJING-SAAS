# 捷境运行环境配置唯一来源与防漂移设计

## 1. 背景

捷境测试环境通过三个私有环境文件向 SaaS 与 Worker 注入配置：

- `tencent-managed.env`
- `jiejing-saas.staging-oauth.env`
- `postgres-localqueue.env`

Docker Compose 会让后加载的文件覆盖前面的同名键，`environment` 区块又会覆盖所有 `env_file`。当前服务器的 `tencent-managed.env` 与 `postgres-localqueue.env` 存在大量重复键，其中包括备份、恢复演练、监控、数据库、队列和安全开关。2026-08-04 已发生一次实际漂移：新的备份与恢复证据写入 `tencent-managed.env` 后，被 `postgres-localqueue.env` 中的旧时间覆盖，固定进度曾从 82/100 暂时降为 79/100。

运行时已经通过同步两份文件恢复为 82/100，但同步写两份文件只处理了当次事故，不能阻止再次发生。

## 2. 目标

- 每个运行时配置键只有一个明确的权威来源。
- 部署前发现未授权的重复键时立即失败，不允许静默覆盖。
- 检查与日志只输出键名、来源文件和分类，不输出任何值。
- 迁移现有私有环境文件时先备份、先 dry-run、遇到不同值时 fail closed。
- 保持测试环境真实平台写入、公开收费、退款、广告和采购能力关闭。
- 不修改固定进度权重，不通过配置技巧虚增完成度。

## 3. 非目标

- 不读取、打印、提交或迁移任何 Secret、Token、API Key、证书私钥或数据库密码到代码仓库。
- 不重复 eBay OAuth 或只读同步。
- 不触发 eBay 草稿、刊登、库存、政策或其他真实写入。
- 不开放真实收费、退款或公开付费上线。
- 不把测试环境改为生产环境。
- 不清理、重建或删除现有数据库、Docker Volume、备份或私有环境文件。

## 4. 方案比较

### 方案 A：配置域唯一归属加部署前重叠检查（采用）

为数据库/队列、OAuth、腾讯云托管能力和 Compose 安全钳位分别定义配置所有权。部署前只读取键名，拒绝任何不符合所有权规则的重复或越界配置。提供独立迁移工具，以 dry-run、备份和冲突拒绝方式清理现有重复键。

优点：从根源消除静默覆盖，错误可解释、可测试、可回滚。缺点：首次迁移需要谨慎分类现有键。

### 方案 B：仅调整 `env_file` 加载顺序（拒绝）

让当前希望获胜的文件最后加载。改动小，但重复键和旧值仍然存在，未来新增配置后还会再次漂移。

### 方案 C：所有工具同时更新多份文件（拒绝）

延续重复配置，通过原子写入同步多份文件。短期兼容，但扩大秘密写入面，任何遗漏都会再次产生漂移，长期维护成本最高。

## 5. 配置所有权

### 5.1 `postgres-localqueue.env`

只负责运行时数据库与队列连接，包括：

- 数据库引擎、适配器和连接地址。
- 队列 Provider、连接地址、Stream、Consumer Group、阻塞时间和死信 Stream。
- 与数据库和队列连接本身直接相关的驱动探针。

它不得拥有备份证据、恢复演练时间、监控告警、腾讯云 SSM/KMS、计费状态、eBay、域名或公开上线状态。

### 5.2 `jiejing-saas.staging-oauth.env`

该文件名是历史名称，当前实际职责是“测试环境后端秘密与敏感 Provider 运行参数”，不只是 eBay OAuth。它可以继续承载：

- eBay OAuth 客户端、回调和 Token/Vault 连接参数。
- 平台模型、公开搜索、媒体生成和微信支付的后端凭证。
- 会话签名秘密和 Vault Token 等只能留在后端的值。

本次不因为文件名过时就移动这些唯一秘密，也不扩大读取或打印范围。它不得拥有数据库/队列连接、备份与监控证据、静态域名配置或可放宽真实写入的开关。后续如需重命名或拆分秘密文件，必须另立规格并单独迁移。

### 5.3 `tencent-managed.env`

负责腾讯云托管资源和运维证据，包括：

- COS 备份、恢复演练、CLS 监控和告警证据。
- SSM/KMS/Vault Provider 配置与安全引用状态。
- 腾讯云区域、托管资源探针和部署证据。
- 国内支付 Provider 的后端状态与受控验收证据，但不包含前端可见秘密。

数据库和队列连接键在迁移完成后不得继续保留在该文件；这些键由 `postgres-localqueue.env` 唯一负责。

### 5.4 Compose `environment`

只保留不可被私有文件放宽的安全钳位与稳定的公开路由配置，例如：

- `JIEJING_ENABLE_REAL_PLATFORM_WRITES=false`
- `JIEJING_EBAY_WRITE_LIVE=false`
- 公共测试环境真实写入策略。

允许的显式覆盖必须登记在代码内的最小 allowlist，并附带原因。普通业务状态和动态证据不得写入 Compose `environment` 形成第三个来源。

## 6. 重叠检查器

新增以键名为主要输入的检查器，接收 Compose 文件与三个私有环境文件路径，输出机器可读的安全摘要：

- 每个键的声明来源。
- 所有权分类。
- 未授权重复键、越界键和 Compose 非法覆盖数量。
- `secret_exposed=false`。

检查器不得读取或打印环境变量值。文件不存在、语法损坏、文件内重复键、关键配置越界、未授权跨文件重复或 allowlist 记录不完整时都必须非零退出。为了不在首次上线时盲目搬动现有唯一秘密，暂未纳入关键所有权清单且只出现一次的旧键可以作为 warning；同一未知键出现在多个来源时仍必须失败。

部署脚本在备份、复制、构建和重建容器之前运行该检查器。检查失败时不得改变服务器状态。

## 7. 迁移工具

迁移工具只在明确指定私有文件路径时工作，默认 `--dry-run`。首次实施只迁移已经纳入关键所有权清单的重复键，不移动只出现一次的模型、搜索、媒体、支付或会话秘密：

1. 解析键名及其归属，不显示值。
2. 对将要移动或删除的重复键比较值是否一致，但输出中只能显示 `equal` 或 `conflict`。
3. 出现冲突时停止，要求操作员先确定真实值；不得自动选择较新文件或后加载文件。
4. apply 前在同一私有目录创建带时间戳且权限不放宽的备份。
5. 只从错误来源删除已确认由另一文件拥有的键；不改变正确来源的值。数据库/队列键保留在 `postgres-localqueue.env`，备份/恢复/CLS/腾讯托管证据保留在 `tencent-managed.env`，后端秘密保留在历史命名的 `jiejing-saas.staging-oauth.env`，静态安全钳位由 Compose 负责。
6. 原子替换文件并保留原有文件权限。
7. 迁移后重新运行重叠检查器。

迁移工具不自动重启容器。容器重建继续走现有 GitHub Actions staging dry-run 与单独 apply 批准流程。

## 8. 部署集成

重叠检查必须接入：

- 本地 staging patch 合同检查。
- GitHub Actions staging deploy dry-run。
- staging apply 的变更前置阶段。
- Runner Doctor 的只读诊断摘要。

dry-run 只报告是否满足所有权合同，不修改私有文件。apply 仍必须在 dry-run 成功后取得独立部署批准。

## 9. 测试设计

按纵向 TDD 逐项完成：

1. 合法的三个文件无重复键时检查通过。
2. 备份时间同时出现在托管文件和数据库文件时检查失败。
3. 数据库连接键只在 `postgres-localqueue.env` 时通过，出现在托管文件时失败。
4. OAuth 键越界到数据库文件时失败。
5. Compose 试图把真实写入开关改为 true 时失败。
6. 已登记的 false 安全钳位覆盖通过。
7. 输出包含冲突键名但不包含测试秘密值。
8. 迁移 dry-run 不写文件。
9. 值不一致时迁移拒绝并保持两个文件不变。
10. 值一致时 apply 先备份，再只删除错误来源中的键，并保持权限。
11. 部署 dry-run 在重叠检查失败时不执行构建、复制或容器操作。

完成聚焦测试后运行仓库要求的 Secret Scan、部署自动化守卫和完整 precloud gate。

## 10. 安全与回滚

- 日志、JSON、测试失败消息和提交内容不得包含环境变量值。
- 任何错误都 fail closed，且保持真实写入和公开收费关闭。
- 迁移回滚只允许从本次迁移生成的精确备份恢复目标文件；不得使用 `git reset`、清理工作区或删除目录。
- 回滚前后都运行键名重叠检查；恢复私有文件后只通过现有受控部署流程重建 SaaS 与 Worker。
- 若线上健康、备份证据或固定进度出现倒退，停止 apply，保留现状并使用本次备份恢复。

## 11. 验收标准

- 已纳入关键所有权清单的重复键被安全迁移；未分类且唯一的历史秘密保持原位并在安全摘要中作为 warning，不得静默复制到其他来源。
- 检查器和迁移工具的测试全部通过，测试证明秘密值不会出现在输出中。
- GitHub Actions dry-run 在重复键场景失败、在合法场景通过。
- 完整 precloud gate 继续全部通过。
- staging apply 后 `/health`、`/health/deep` 和 `/readiness/product-saas` 均为 HTTP 200。
- 固定进度不低于迁移前真实值 82/100。
- `production_ready=false`、`can_accept_real_customers=false`、`public_charging_allowed=false` 和 `real_platform_writes_enabled=false` 保持不变。

## 12. 主理人审视结论

本设计不增加商家可见功能，也不直接增加固定商业进度，但它解决的是 SaaS 上线必须具备的“配置事实只有一个来源”和“部署失败可解释”能力。它符合捷境作为 eBay-first AI CEO SaaS 的方向：把复杂运维留在内部，把商家体验保持简单，同时确保经营事实、授权数据、高风险动作和上线声明都有可追溯的真实证据。
