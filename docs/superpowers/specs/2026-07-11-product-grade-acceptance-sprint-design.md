# 捷境产品级验收冲刺设计

日期：2026-07-11

## 目标

把捷境从“功能已经形成闭环”推进到“闭环可以重复验收、故障可以解释、上线边界有证据”的受邀商家产品。产品定位保持为 eBay-first AI CEO SaaS，不扩成通用 ERP、通用 Agent 市场或普通聊天工具。

## 验收主旅程

使用全新、明确标注为验收数据的轻小件商品事实包，按以下顺序运行：

1. 商家向 AI CEO 提出选品需求。
2. AI CEO 生成结构化市场调研与多个候选商品。
3. 商家选择一个候选商品，系统只把该商品的结构化事实导入 Listing。
4. 商家补充价格、图片、物流和平台必填资料。
5. 素材工坊生成或导入图片/视频，形成 AssetManifest，审核后回写同一个 Listing 项目。
6. 批量铺货可独立导入，也可接收 Listing 项目；所有条目先经过字段和风险体检。
7. 系统生成发布确认单并进入决策中心。
8. 验收止于人工确认边界，不写入 eBay、不扣款、不修改库存、价格或政策。

每一步必须保留稳定的 project_id、source records、work records、confirmation items 和商家可读状态。聊天文本不能直接充当 Listing 字段；模型猜测不能伪装成商品事实。

## 产品体验原则

- AI CEO 普通咨询保持连续对话；eBay 经营意图才进入工作流。
- 等待状态简洁、即时、可取消；长任务提供阶段进度，不暴露 Provider 或内部排查术语。
- 设置是账号、店铺、授权、模型、素材、权限和上线状态的控制室；经营报告和 Listing 结果不放入设置。
- 初级商家只看到“现在做什么、还缺什么、下一步是什么”；技术字段和详细证据按需展开。
- 桌面、平板和移动端保持同一账号状态与历史，不依赖单设备缓存作为事实来源。

## 可靠性与安全

- AI、联网搜索和素材生成使用明确超时、有限重试、幂等键和可恢复任务状态。
- 跨设备同步使用账号级服务端事实、客户端合并和冲突规则；店铺只是任务上下文。
- 昂贵接口按账号限流；队列任务可重试但不能重复产生外部副作用。
- 所有资源校验 company_id、user_id、store_id 和权限；公共 ID 不使用可猜测自增序号。
- API key、token、refresh token、client secret 和支付密钥只在 Vault/env 边界处理，不进入前端、报告、日志或测试夹具。
- 备份验收必须包含恢复演练证据，不能只证明“生成了备份”。

## eBay 与支付边界

本轮只完成可执行的上线准备，不触发外部真实动作：

- eBay：准备新账号只读授权检查单、Token refresh 证明门禁和低风险 draft/save 验收入口。没有用户明确提供的新账号测试许可时，不运行 OAuth 或真实写入。
- 支付：保留测试 Provider 和受邀 Beta 额度；完善正式 Provider 配置检查、签名 webhook、幂等、套餐映射和回滚门禁。不进行真实扣款、退款或额度人工冒充发放。

## 发布门禁

每次重要改动必须通过：

1. 主旅程自动化回归。
2. 前端桌面和平板/移动端浏览器验收，控制台无相关错误。
3. 租户隔离、权限、限流、队列恢复、备份恢复和审计测试。
4. secret scan、语法检查、数据库迁移演练和 public staging 代理契约。
5. 部署后 `/health`、`/health/deep`、`/readiness/product-saas` smoke。

`production_ready=false`、`can_accept_real_customers=false` 或真实 Provider 证明缺失时，页面和汇报都必须保持诚实，不得宣称正式收费上线。

## 完成定义

- 主旅程可以用同一套全新验收数据重复运行，且不会触发真实外部写入。
- AI CEO、Listing、素材、批量和决策中心之间共享同一项目身份，没有聊天全文误填字段。
- 失败可以定位到具体阶段并给商家可执行的下一步，不再只显示“连接不稳定”。
- 设置页不出现内部运营汇报、开发术语或与当前商家无关的收款建议。
- 第 6 项的外部阻塞被代码门禁和运行手册精确表达；在新 eBay 账号和正式支付 Provider 到位前保持 blocked，而不是伪造通过。
