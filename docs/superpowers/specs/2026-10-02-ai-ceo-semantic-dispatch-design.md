# AI CEO 语义调度与商品隔离

## 已确认的范围

2026-10-02 用户确认：保留现有产品，重构业务理解与调度；通过原商品回归、新商品、无货源调研三个网页流程验收。不是重做 UI、另建平台或放开真实发布。自然语言无需固定关键词；大模型负责意图与规划，程序负责身份、权限、来源、并发和执行限制。

## 决策

- 不采用继续增加关键词的方案：不能覆盖自然表达，且不能解决判断前保存图片的顺序错误。
- 不采用整站重写或让模型直接操作数据库：浪费既有执行能力，损失隔离和审计。
- 采用服务器唯一语义计划。使用现有后端模型连接和用量记录；结构化计划通过严格字段校验后，才能选择商品并调用既有工具。浏览器只呈现服务器结果。

## 数据流

1. 验证登录、店铺、附件归属并领取已有幂等请求；不改变商品事实。
2. 在现有额度预留/模型计量内调用语义规划。输入用户原文、有限对话、经服务器核对的当前商品上下文和附件元数据；不发送密钥。
3. 计划指定任务、继续/新建/无商品/需要澄清、资料整理与搜索需求。枚举和长度严格验证；模型不能指定公司、店铺、任意数据库主键、权限或真实写入开关。
4. 当前商品必须有同商家同店铺的持久化证据。新商品身份由服务器为当前请求生成；计划不清楚或无效时不继承旧商品，不保存商品事实，返回明确澄清或失败。
5. 图片识别与报告保存只在计划确定后执行；新项目不携带旧商品事实。Listing、素材队列、保存和确认中心复用既有受控执行模块。
6. 结果返回服务器验证过的计划与商品身份。前端只在仍处于提交时上下文时投影结果，不凭关键词预先清空旧项目；刷新/重试复用已归档结果。

## 保持的限制

### 研究交付与来源契约

语义计划增加两个严格字段，由模型选择，服务器不再从用户原文关键词重新分类：

- `research_delivery`：`candidate_selection`（寻找或更换候选）、`evidence_comparison`（已有候选补证比较）、`single_product_analysis`（单个商品分析）、`none`。就绪的 `research` 任务必须使用前三项之一；其他意图使用 `none`。
- `research_queries`：最多 3 组且每组恰好包含 `{subject, query}`。仅 `research + web_search` 必须提供 1–3 组，其他情况为空数组；顶层 `query` 与第一组相同。`subject` 最多 120 字、查询最多 900 字；只有开放候选发现允许空 `subject`，其他研究交付必须指定主体。不接受公司、店铺、任意主键或额外执行字段。

模型提供具体商品检索名或待验证方向和查询后，仍复用既有商品搜索执行器：每组独立检索、过滤非 eBay 商品页与无关商品、为各组优先保留一个来源、合并最多 5 条来源并保留 `product_research_evidence` 和逐查询覆盖记录。原有最多 3 次搜索及最多 5 条模型来源窗口保持不变；`candidate_count` 保持既有 1–5 边界，不增加搜索或模型调用预算。没有合格商品来源时不得把回答标成已完成研究成果。

回答验收按 `research_delivery` 分派：仅候选选择要求候选卡；成交补证比较复用已有提交证据、相对赢家和供应商核验衔接检查；单品分析不强制产生其他候选。各交付类型仍做来源归属和平台依据校验。开放发现即使 `subject` 为空，也必须在回答后逐候选核对其引用商品页与名称是否相关；不能把相机背带来源归给量勺。中英文名称对应仅来自计划中明确的双语主体（中文名 / 检索名），不把不同的 `product_name` 与 `subject` 自动当成别名，也不能借此创造供应商事实。研究交付类型、查询列表完整保留在公开计划与归档回执中。

### 本条文字资料的待确认提案

为保留既有纯文字商品资料输入，计划必填 `product_fact_proposals`（无资料时为 `[]`）。仅 `ready + new/current + save_artifact=true` 可非空，最多 16 项；每项恰好包含 `{field, value, source_quote}`，不得重复字段。字段白名单直接复用 `MERCHANT_PRODUCT_FACT_KEYS`，排除 `image_rights_confirmed`、`merchant_owned_product_confirmed`；商品 SKU、MPN、供应商货号属于普通资料，不允许公司、店铺、报告或项目身份字段。

`value` 为最多 240 字的非空字符串，须通过既有商品资料 normalizer 且清洗前后逐值相同；数字字段使用纯数值，URL 与敏感信息检查沿用现有规则。`source_quote` 为最多 160 字的非空片段，必须逐字来自本条原始消息，不能拿历史商品、附件或网页补出处。提案的值与引用均检查秘密形态，未知字段、伪造出处、无效数值或授权注入整体拒绝。引用证明可追溯，不代表内容已被独立核实；提案只进入待确认建议，不自动确认商品事实、所有权或图片权利。

规划器使用既有提供商支持的 4096 输出 token 上限与原计量边界；原始响应仍限 16000 字，`finish_reason=length` 即使返回可解析 JSON 也拒绝，不把被截断结果视为完整计划。公开计划完整保留提案供后端绑定/安全合并与审计；实际资料合并、当前商品版本和商家已确认值保护复用后端既有流程。

模型理解不是执行授权。真实发布、付款、退款、政策与客服敏感承诺保持确认门禁。未知商品事实不得变为已确认事实。规划与回答的真实提供商调用均计入已有用量记录；不增加新套餐或自行改变体验次数规则。超时/无效计划不降级为关键词自动执行。

## 验收终点

- 原冒号触发、新说法、否定、引用、模糊续接均由受控模型计划驱动，而非固定口令。
- 新旧项目及其他商家资料不串；模糊输入和模型故障不改变商品。
- 保存、刷新、导航和重复请求能续接；既有三项局部衔接修复保留回归。
- 完整代码门禁、发布预演及授权部署后，在捷境真实网页依次验 A/B/C 至发布前。没有实际 eBay 成功不得声称真实发布；未部署不得声称线上已修复。

## 实施计划

1. 模型计划契约及无副作用校验：真实公共接口 RED→GREEN，外部模型使用测试替身。
2. 后端入口先规划后绑定/保存；幂等、用量、失败恢复与来源校验回归。
3. 前端不再决定项目；服务器结果承接与刷新/迟到响应回归。
4. 关联校验统一采用计划；安全审查、定向与完整门禁；候选包/部署预演。
5. 正式部署需本批明确授权；随后实际网页 A/B/C，保留每项证据和真实未完成项。
