# 捷境新卖家向导闭环设计

日期：2026-08-02  
状态：待书面确认  
范围：补全现有 `newbie` / “新店起步”向导，不新增第二套入门系统

## 1. 目标

把当前“解释型向导”补成一条新手可以真实走完、刷新后不丢、回到捷境后知道下一步的 eBay-first 入门闭环：

1. 先判断商家是否已有 eBay 卖家账号和 Seller Hub 能力。
2. 尚未开通的商家从捷境进入 eBay 官方卖家注册页，在 eBay 完成身份、地址、收款及平台要求的验证。
3. 商家返回捷境后从原步骤继续，不重复回答、不把自报完成冒充官方验证。
4. 只有没有当前有效连接时，才由商家本人显式发起一次 eBay 官方授权。
5. 有有效连接后使用已有只读数据和账号健康证据判断卖家注册、账号限制和三类 Business Policies 状态。
6. 条件未齐时仍允许调研、素材和 Listing 草稿，但真实发布始终受发布体检、决策中心和后端写入边界约束。

本改动提升新手激活与真实商家流程完整性，不改变固定商业上线进度分值，也不构成真实收费或正式公开上线证据。

## 2. 当前事实与缺口

### 2.1 已有能力

- 官网 `index.html` 已有 `newbie` 路径，覆盖 eBay 卖家注册、官方授权、业务政策、货源履约、素材和第一条 Listing。
- 工作舱 `app.js` 已有“新店起步”路线和 eBay 官方开店页 `https://www.ebay.com/sl/sell`。
- 后端已有 `GET /stores/{store_id}/account-health`，可给出：
  - `seller_registration_required`
  - `account_review_required`
  - `business_policies_required`
  - `ready_for_publish_preflight`
- 付款、配送、退货三类 Business Policies 必须同时存在，才算政策就绪。
- 当前账号健康文案已经明确：授权仍有效但卖家注册未完成时，不应重复 OAuth。

### 2.2 必须补齐的缺口

- 用户在向导中选择“还没注册”后，没有在当前步骤立即看到官方注册主按钮。
- `guideAnswers` 只存在当前页面内存，完成标记和路径只存本机 `localStorage`；刷新、换设备或清缓存后不能可靠恢复。
- “完成向导”与“卖家账号已就绪”混为一个动作，用户可跳过后被误认为已经完成卖家准备。
- 从 eBay 返回后没有明确的“我已回来—继续检查”状态，也没有基于真实账号健康决定下一步。
- 自报“已完成注册”、OAuth 状态、只读数据和三类政策状态尚未组成单一状态机。
- 已有当前有效授权时，向导没有用统一规则隐藏重复授权入口。

## 3. 设计原则

1. **一条向导**：继续使用现有官网入门向导和工作舱“新店起步”，不创建重复页面或平行状态源。
2. **一次只给一个主动作**：每个阶段只突出注册、授权、只读检查或补政策中的一个。
3. **事实高于自报**：商家选择用于决定引导；后端只读证据用于决定验证状态和真实动作门槛。
4. **可先做草稿，不可假装就绪**：跳过只改变工作模式，不改变卖家注册、政策或发布就绪状态。
5. **不碰 eBay 私密资料**：捷境不收集 eBay 密码、验证码、身份证件、银行卡、收款凭证或注册地址明细。
6. **不重复 OAuth**：存在当前有效连接时，只刷新只读数据；只有连接缺失或后端明确判定失效，才显示重新连接入口。
7. **没有真实写入**：向导、只读检查和本次测试不得触发发布、改价、库存、政策、广告、退款、付款或采购写入。
8. **商家语言优先**：前台不用 token、packet、preflight、provider、Vault 等内部术语。

## 4. 用户体验与状态流

### 4.1 顶层状态

界面同时展示两个互不混淆的状态：

- **入门偏好进度**：用户已经回答到哪一步、选择了什么经营方式。
- **eBay 开店准备状态**：根据后端证据判断当前下一步。

eBay 开店准备状态只有以下值：

| 状态 | 商家看到的名称 | 唯一主动作 | 允许范围 |
| --- | --- | --- | --- |
| `seller_registration_required` | 完成 eBay 卖家开通 | 打开 eBay 官方卖家注册 | 可做调研、素材、Listing 草稿 |
| `seller_registration_returned` | 已返回，等待官方检查 | 继续连接并检查 | 不宣称注册已验证 |
| `authorization_required` | 连接 eBay 店铺 | 连接 eBay 官方授权 | 只有商家本人可发起 |
| `read_only_check_required` | 读取最新店铺状态 | 刷新只读状态 | 不触发 OAuth 或写入 |
| `account_review_required` | eBay 账号需要处理 | 查看处理清单 | 只允许诊断、证据和只读同步 |
| `business_policies_required` | 补齐店铺规则 | 打开政策设置说明 | 三类政策缺一不可 |
| `ready_for_publish_preflight` | 可以准备第一条商品 | 开始 Listing 草稿与发布体检 | 真实发布仍需决策中心 |

`seller_registration_returned` 是捷境流程状态，不是 eBay 官方验证结论。其作用只是记住用户已经从官方页面返回，并把下一步收敛到连接或只读检查。

### 4.2 新用户路线

#### A. 还没有 eBay 卖家账号

1. 当前步骤显示资料说明和“打开 eBay 官方卖家注册”主按钮。
2. 外链在新窗口打开，使用固定官方允许列表与 `noopener,noreferrer`。
3. 页面立即保存 `seller_registration_required`、当前步骤及用户选择到后端。
4. 用户回到捷境后，页面显示“我已回到捷境”，主按钮为“我已完成 eBay 页面，继续检查”。
5. 点击后只把流程状态设为 `seller_registration_returned`；不得直接标记 `verified`。
6. 如果还没有有效连接，下一步由商家本人点击“连接 eBay 官方授权”。
7. OAuth 回调成功后运行现有只读同步并读取账号健康；若卖家注册仍未完成，回到 `seller_registration_required`，同时显示“连接仍有效，无需重新授权”。

#### B. 已有卖家账号但不熟 Seller Hub

1. 保存选择后进入 `authorization_required`，提供简短的 Seller Hub 说明。
2. 若已有当前有效连接，跳过授权，直接进入 `read_only_check_required`。
3. 只读检查后按真实账号状态进入账号处理、政策补齐或 Listing 准备。

#### C. 已能进入 Seller Hub / 已有店铺订阅

1. 直接依据当前连接状态进入授权或只读检查。
2. 店铺订阅只作为费用核算背景，不作为卖家注册或发布就绪证明。

### 4.3 暂时跳过路线

“保存并进入工作舱”保留，但改成以下语义：

- 保存为 `draft_only` 工作模式；
- 入门问答可以标记为“已保存”，不能标记为“eBay 开店已完成”；
- 工作舱持续显示“eBay 开店待完成”及返回入口；
- 可以进行市场调研、货源整理、素材生成和 Listing 草稿；
- 发布体检和后端执行边界继续阻止真实写入；
- 不因跳过向导而触发 OAuth、付款或任何平台动作。

### 4.4 回站检测

- `visibilitychange` / `focus` 仅用于展示“欢迎回来”和恢复按钮，不能据此判断注册成功。
- 不轮询 eBay 页面，不读取第三方页面内容，不做 iframe、浏览器扩展或表单代填。
- 有当前有效连接时，用户点击“刷新店铺状态”只执行已有只读同步。
- 只读同步失败时显示原连接仍保留，并给出“重新检查”按钮；不默认展示重新授权。
- 只有后端连接状态为缺失、撤销或失效时，才显示授权动作。

## 5. 状态判定优先级

统一状态计算器按以下优先级输出唯一 `effective_stage`：

1. 后端发现账号受限、冻结、收款冻结、额度阻断或缺少可追溯快照：`account_review_required`。
2. 后端账号健康为 `registration_incomplete`：`seller_registration_required`。
3. 没有当前有效 eBay 连接：
   - 用户尚未声明从官方注册页返回：`seller_registration_required`；
   - 用户已声明返回或本来已有卖家账号：`authorization_required`。
4. 有有效连接但尚未获取最新可用只读证据：`read_only_check_required`。
5. 三类 Business Policies 任一缺失：`business_policies_required`。
6. 账号正常、只读证据存在且三类政策齐全：`ready_for_publish_preflight`。

前端不得提交 `effective_stage` 或 `verified=true` 来覆盖此结果。前端只提交允许的问答、当前步骤、跳过模式和“已从官方页面返回”这类用户意图；验证状态由后端组合连接、账号健康和只读证据得出。

## 6. 数据模型

新增公司级、可选店铺绑定的 `merchant_onboarding_states`：

| 字段 | 说明 |
| --- | --- |
| `company_id` | 租户主键的一部分 |
| `onboarding_key` | 固定为 `primary_ebay`，与公司组成联合主键 |
| `store_id` | 初始可为空；首个 eBay 店铺创建后绑定 |
| `path_key` | `newbie`、`store_opened`、`has_orders`、`multi_store` |
| `current_step_key` | 当前向导步骤，使用固定允许列表 |
| `work_mode` | `guided` 或 `draft_only` |
| `seller_returned` | 用户是否声明已经从 eBay 官方注册页返回；不代表验证成功 |
| `answers_json` | 仅保存枚举化的经营偏好，不保存自由文本敏感资料 |
| `completed_step_keys_json` | 已保存的向导步骤列表 |
| `version` | 乐观并发版本号，防止多窗口覆盖新进度 |
| `updated_by_user_id` | 最近操作人 |
| `created_at` / `updated_at` | 审计时间 |

返回对象额外包含后端派生字段：`effective_stage`、`stage_label`、`next_action`、`connection_current`、`account_health_evidence_present`、`business_policies_complete`、`publish_preflight_available`、`secret_exposed=false`。

约束：

- `answers_json` 只接收已定义 key 和 enum；拒绝未知 key、过长值及 secret-like key。
- 不保存密码、token、OAuth code、身份证件、银行卡、地址明细、验证码、Cookie、原始 eBay 页面内容。
- 不以邮箱作为主键，不向 analytics 发送用户原始回答或第三方账号身份。
- 团队成员读取同一公司进度；只有具备店铺管理权限的成员可修改卖家连接相关步骤。
- 所有读取和写入必须使用认证身份中的 `company_id`，不得接受客户端传入公司范围。

## 7. 后端结构与接口

新增独立领域模块 `jiejing_saas/merchant_onboarding.py`，负责：

- 允许的路径、步骤和回答枚举；
- 输入规范化与敏感字段拒绝；
- 组合持久化状态、连接状态和 `account_health`；
- 输出唯一下一步和商家文案；
- 保证 `draft_only` 不改变任何真实执行门槛。

新增认证接口：

### `GET /merchant-onboarding/primary-ebay`

读取当前公司向导状态；若已绑定店铺，同时合并当前连接和账号健康。若尚无记录，返回安全默认状态，不自动写库、不自动发起 OAuth。

### `POST /merchant-onboarding/primary-ebay/progress`

只接受：

```json
{
  "path_key": "newbie",
  "current_step_key": "ebay_stage",
  "work_mode": "guided",
  "seller_returned": false,
  "answers": {
    "ebay_stage": "not_registered"
  },
  "completed_step_keys": [],
  "expected_version": 0
}
```

行为：

- 服务端按允许列表清洗并 upsert；
- 版本冲突返回 `409` 和最新安全状态，前端重新合并，不静默覆盖；
- 返回后端派生的 `effective_stage` 和唯一下一步；
- 写入隐私安全审计事件，只记录阶段变化和动作类型，不记录原始回答内容；
- 不触发 OAuth、只读同步、付款或真实平台写入。

现有 OAuth、只读同步和 `account-health` 接口继续作为动作与证据来源，不在进度保存接口中隐藏调用。这样用户点击了什么、系统读取了什么、真实状态是什么可以分别审计。

## 8. 前端改造

### 8.1 官网原向导 `index.html`

- 保留现有入口、视觉结构和路径选择。
- 登录成功后先读取后端向导状态，再渲染步骤；后端不可用时才以本机状态只读兜底，并明显提示“进度暂未同步”。
- 每次步骤选择和前后移动都做防抖保存；离开页面前尽力保存，但不依赖 `beforeunload` 才保存。
- `ebayStage=not_registered` 时在当前卡片内显示官方注册主按钮，不再让用户到工作舱寻找隐藏入口。
- “完成向导”改成“保存设置并进入工作舱”；状态摘要同时显示“入门设置已保存”和真实 eBay 准备状态。
- 旧 `localStorage` 只用于一次性迁移：后端无记录时可导入 `path` 和是否看过向导；旧 `done=1` 只能映射为“偏好已保存”，不能映射为卖家已验证。

### 8.2 工作舱 `app.js`

- “新店起步”卡片读取同一后端状态，不维护第二份完成标记。
- “去 eBay 官方注册卖家账号”、OAuth、账号健康和三类政策说明复用现有动作定义。
- 账号健康已是 `registration_incomplete` 且连接当前有效时，主按钮只能是“继续 eBay 卖家注册”或“刷新只读状态”，不能出现“重新授权”。
- 三类政策显示逐项状态：付款、配送、退货；任何一项缺失都保持“发布前待补”。
- 就绪文案必须为“可以进入发布体检”，不能写“已经可以自动发布”或“正式上线完成”。

### 8.3 响应式与可访问性

- 手机端一列卡片，底部主动作不遮住正文，外链返回后仍回到当前步骤。
- 主按钮、次按钮和状态文字保持现有设计系统的视觉层级；每屏只突出一个主动作。
- 状态变化使用可读文本和颜色双重表达，不能只靠红绿颜色。
- 键盘可访问，焦点从外链返回时落在“欢迎回来/继续检查”区域。

## 9. 商家文案基线

- 未注册：`先去 eBay 官方完成卖家开通。身份、地址和收款资料只提交给 eBay，捷境不会向你索取 eBay 密码。`
- 返回未验证：`欢迎回来。点击继续后，捷境会带你连接官方授权并读取店铺状态；这一步不会发布商品。`
- 注册仍未完成：`你的 eBay 连接仍然有效，无需重新授权。请先回 eBay 完成卖家资料、地址或收款验证。`
- 政策缺失：`账号已经能使用，但付款、配送、退货三类店铺规则还没有全部准备好。可以先做草稿，发布前必须补齐。`
- 准备就绪：`eBay 卖家资料和三类店铺规则已可读取。下一步先做商品资料和发布体检；真实发布仍要你确认。`
- 跳过：`已保存为草稿模式。你可以先做调研和 Listing 草稿，eBay 开店和真实发布仍保持暂停。`

## 10. 安全与威胁边界

- 官方链接使用固定允许列表，不接受服务端或用户输入的任意跳转 URL，防止开放重定向与钓鱼。
- OAuth `state`、回调、凭证托管沿用现有后端边界；向导表不保存任何凭证引用之外的秘密值，且前端不接触 token。
- 所有进度接口要求认证、公司范围隔离和权限检查；针对跨租户读写加入负向测试。
- `answers` 严格使用 JSON schema/允许列表并限制请求体大小，防止把自由文本、HTML 或秘密数据塞入持久化状态。
- 审计和 analytics 只记录事件名、路径、步骤、阶段和安全布尔值，不记录邮箱、原始 URL、IP、User-Agent、eBay 用户名或注册资料。
- 页面不得承诺代填 eBay KYC、绕过验证码、绕过地区规则或保证开户成功。
- 任意状态下，发布、改价、库存、广告、退款、政策修改和付款仍走现有确认中心与后端执行门槛。

## 11. 错误与恢复

- **后端保存失败**：保留当前页面选择，显示“进度暂未同步”，提供重试；不得假装保存成功。
- **版本冲突**：加载服务器较新版本，保留用户当前未提交选择，并让用户再次确认差异。
- **OAuth 取消/失败**：返回原步骤并说明未完成连接；不删除已有连接，不改变草稿数据。
- **只读同步失败**：保留当前授权，显示“读取失败，可重新检查”；只有后端判定连接失效才提供重新授权。
- **账号注册未完成**：显示 eBay 官方处理清单和注册入口；不反复要求 OAuth。
- **账号受限/冻结**：进入事故模式，只允许只读诊断与证据；不得引导真实发布。
- **政策不完整**：逐项显示缺失政策，允许继续做草稿，但不得进入真实写入。
- **没有店铺记录**：公司级进度正常保存；首个 eBay 店铺建立后再绑定，不能因 `store_id` 为空丢失进度。

## 12. 测试与验收

### 12.1 后端合同

1. 未认证读取/保存进度返回 `401`。
2. 公司 A 不能读取或更新公司 B 的进度。
3. 未知答案 key、未知 enum、过长字段、secret-like key 返回 `400`。
4. 新用户无店铺也能保存并恢复进度。
5. 首个 eBay 店铺创建后能安全绑定原公司级进度。
6. `expected_version` 冲突返回 `409`，不覆盖服务器新状态。
7. 前端伪造 `effective_stage`、`verified`、`connection_current` 不生效。
8. `draft_only` 不改变真实写入、收费、OAuth 或发布门槛。
9. 持久化记录、接口响应、审计记录和日志均无 secret、token、密码和身份资料。
10. SQLite 与 Postgres 路径行为一致。

### 12.2 状态机

1. 无账号、无连接：注册入口。
2. 用户声明返回但无连接：授权入口，不显示“已验证”。
3. 有当前有效连接且账号 `registration_incomplete`：注册入口，并明确无需重新授权。
4. 有当前有效连接但只读快照缺失/过期：只读检查入口，不触发 OAuth。
5. 账号受限或冻结：账号处理入口，所有真实动作暂停。
6. 账号正常但三类政策缺任一项：政策入口。
7. 账号正常、快照有效、三类政策齐全：进入发布体检，不直接发布。

### 12.3 前端与浏览器

1. 选择“还没注册”后，当前步骤立即出现正确的 eBay 官方注册链接。
2. 打开外链后返回原窗口，焦点落在“欢迎回来”，原进度不丢。
3. 刷新、退出重登和另一浏览器登录后，服务端进度一致。
4. 跳过后显示草稿模式和未完成状态，不显示“eBay 已就绪”。
5. 有有效连接时不出现重复 OAuth 主按钮。
6. 付款、配送、退货三类政策逐项可见，缺一项即保持阻断。
7. 桌面、平板和手机无横向溢出、无按钮遮挡，键盘可操作，控制台无错误。
8. 页面不暴露内部运营后台、供应商名称、诊断明细或 Hermes 字样。

### 12.4 回归与安全门禁

- 添加聚焦的 repository、API、状态机、租户隔离、前端合同和浏览器冒烟测试。
- 保持现有登录、已有店铺向导、账号健康、OAuth 回调、只读同步、Listing 草稿和确认中心行为不倒退。
- 运行相关 JS/Python 检查、秘密扫描和完整 precloud deployment gate。
- 测试只使用模拟或安全只读数据；不触发真实 eBay 写入、真实付款、退款、广告、采购、改价、库存或政策修改。

## 13. 实施顺序

1. 增加 `merchant_onboarding.py` 状态机及单元测试。
2. 增加 SQLite/Postgres 兼容表、repository upsert/get、审计记录及租户隔离测试。
3. 增加认证 GET/POST 接口及输入/冲突/权限测试。
4. 改造官网现有向导，接入服务器状态、官方链接、回站恢复和草稿模式。
5. 改造工作舱读取同一状态，并将账号健康、OAuth 与三类政策映射到唯一下一步。
6. 完成桌面/手机浏览器冒烟、秘密扫描、聚焦测试与完整上线门禁。
7. 仅生成新的部署包与证据，不改变商业上线分值；部署和真实账号操作另走现有批准边界。

## 14. 非目标

- 不代替用户填写或提交 eBay 身份、企业、地址、银行、收款、验证码或 KYC 表单。
- 不抓取、嵌入或自动操作 eBay 注册页。
- 不新增其他平台 onboarding、通用 ERP 引导或 Agent 市场。
- 不自动创建/修改 eBay Business Policies。
- 不在本改动中重复旧 OAuth，不使用冻结账号，不进行真实平台写入。
- 不把此功能完成计入支付验收、Token 续期证明、真实商家完整流程或最终商业上线批准分值。

## 15. 完成定义

只有以下条件全部满足，才能声称“新卖家向导闭环已完成”：

- 现有同一向导能够保存、恢复并正确展示唯一下一步；
- 官方注册返回不被误判为卖家验证完成；
- 当前有效连接不会被重复 OAuth；
- 账号健康和三类政策真实证据能驱动状态机；
- 草稿模式可用但真实发布保持阻断；
- 后端持久化、权限、租户隔离、秘密边界及 SQLite/Postgres 测试通过；
- 桌面和手机浏览器验收通过；
- 完整部署门禁继续通过；
- 未发生真实 eBay 写入、真实收费或进度虚增。
