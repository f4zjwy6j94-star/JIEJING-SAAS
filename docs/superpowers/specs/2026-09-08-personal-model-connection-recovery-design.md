# 个人 AI 连接恢复与错误分类修正

## 已批准目标与边界

用户在确认历史记录后批准先恢复既有个人 API，并修正需要反复提醒才能定位的问题。本轮保持平台体验专用连接、7天/20次规则、现有个人连接优先路由、商品项目与 eBay/资金权限不变。不新增通用恢复平台或无实现的恢复按钮。

## 已核实问题

同公司两条个人可见模型引用曾进入 ready，2026-07-10 后被标记为旧腾讯云 SSM 读取受阻。公共设置、检测接口和前端却统一解释为首次保存失败，要求重新输入。这一推断错误；历史成功也不能反向证明今天密钥有效。

## 最小方案

1. 恢复原连接优先：按精确公司/账号/店铺/引用身份检查当前 Vault 对应路径元数据，必要时检查旧 SSM 的既有恢复条件。只检查元数据和布尔能力，不读取或输出模型密钥、云凭据、完整私有配置。没有充分依据不改 ready、不改 Vault 权限、不购买 KMS、不复制平台 key。只有确认同一凭证可恢复后，才另行执行后端安全恢复及有效性验证；不能恢复时明确需要用户安全重存的最小资料。
2. 分类修正：只有严格历史写入成功证据与当前存储读取受阻信号同时成立，才标记 `storage_recovery_required`。保持 configured=false、不能直接调用模型；不误称首次保存失败，也不要求立即重填。只存在引用、创建日期或旧失败状态不足以触发该分类。
3. 保留正确行为：首次保存失败仍按现有路径处理；stored_unverified 仍可重新检测；其他可用连接优先，旧失联引用不能遮蔽它；不能跨账号或公司选取连接。
4. 页面说明曾保存但暂不可读取，需先恢复；不声称自动恢复正在执行或必然成功。检测接口对已知恢复受阻返回同一准确原因，不循环读取不可用旧存储或调用模型。

## 验收

- 用真实本地 HTTP 设置/检测接口复现 ready→blocked 的生命周期，先失败再修复；验证无 resolver/provider 调用。
- 覆盖首次失败、历史证据缺失/伪布尔、可重新检测状态、其他 active 连接和账号隔离。
- 真实前端 renderer 验证恢复提示及按钮/进度状态；保留原失败 fixture。
- 本地专项、语法和秘密扫描通过；相关合同进入持续门禁。
- 代码修正完成不等于真实凭证恢复，也不等于已部署。正式部署遵循现有新候选验证和动作确认，不复用前版 228 项证明。

## 执行顺序

元数据恢复探针与本地合同修正并行 → 独立审查 → 汇总恢复条件和真实结果 → 如能安全恢复则继续原商品有效生成；否则精确说明外部阻断并保留本地修复，不编造生成成功。

## 本轮恢复调查进展

元数据阶段完成后，已按用户“先恢复”授权检查一个精确个人账号引用的后台可读性。旧 SSM 的精确派生名称命中、记录启用；当前 Vault 对应元数据 404。只在原生产后端执行一次版本列表和一次取值请求，不把值交给工具或前端、不写库、不迁移、不调用模型。取值阶段返回 `FailedOperation.AccessKmsError`，因此未获得可迁移内容，真实连接尚未恢复。历史引用存在和启用不能代替实际读取或模型有效性证明。后续只能核对服务状态、寻求原服务恢复或由用户在安全设置中重存个人连接；不能擅自购买 KMS、改变访问权限或复制平台专用凭证。

本地复核另发现账号 AI 面板禁用生成按钮与可用按钮外观相同；本轮一并最小修正其禁用视觉状态，不更改布局或业务可用性。

最终只读服务状态：SSM 正常；KMS `ServiceEnabled=false, InvalidType=3`，官方定义为资源释放。现有旧路径无法取回，不代表已证明具体密钥永久销毁。没有购买服务或改权限，推荐在安全设置中重存个人连接以恢复当前 Vault 路径，而不是新增付费 KMS 依赖。

## 不依赖密钥的下一步：辅助请求超时清理

用户随后明确人在外面，要求不要等待密钥、继续推进。本批并入已经证实的 `optionalSaasFetchFast` 定时器问题：请求提前成功或失败后未清理软超时定时器，导致之后追加超时诊断和重复计算 fallback。现有诊断列表没有运行时界面消费者，不能据此断言成功数据被覆盖，也不能归因所有历史 502。

最小修正保持原软超时预算、后台请求及会话失效处理；已完成的请求必须清理定时器，真正超时仍返回降级值且只记录一次，迟到失败不得重复调用降级回调。不改变商品、额度、模型选择或发布门禁。

验收在既有完整前端韧性 smoke 中使用真实 app、本地 HTTP 和浏览器虚拟时钟，先复现成功后假超时，再覆盖提前失败、真实超时、迟到失败及鉴权边界。新测试不需要真实模型、FAL 或 eBay；新候选仍需完整门禁及部署动作确认。
