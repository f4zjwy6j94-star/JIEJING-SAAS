# Listing 登录过期后的生成续接保护

日期：2026-09-10。范围：已授权商家旅程中发现的恢复缺口；不改套餐、权限、产品结构或视觉布局。

## 现场与目标

用户重新登录后，原平板支架项目及云端检查点仍存在：project `listing-project-0ef70f19c079b4261e82`、base `report_product_facts_f205506e776595b0584d2fbdeaf158192ec52f51`、revision 6。页面显示已云端保存，但上次未登记生成操作 `743c4370-6ffd-48fa-97ab-bedd060380c8` 的恢复入口消失。最近任务返回草稿后仍指引查看不存在的生成反馈。

既有代码的会话失效路径删除账号保护快照并清空内存；普通认证状态下刷新恢复测试没有覆盖失效后重新登录。数据库商品资料丢失、模型密钥丢失、旧版静态资源加载均不符合本次已观察证据；当前页面加载 01eb477 的 JS 资源族。

目标是保存足以核对同一次生成的最小元信息，并在重新认证后安全恢复入口。不是恢复旧认证、自动重新生成、补写历史操作或重建商品。

## 方案选择

- 不选整体保留保护快照：其中含账号、权限、报告、媒体等超出续接需要的数据。
- 采用最小元信息记录：在既有账号作用域命名空间下使用独立 `:pending_listing_generation` 存储键及版本，不占用普通保护快照。仅保留原操作编号、完整 user/company/store/project 身份、生成模式、原 base/revision、原摘要、结果 ID 与严格状态；记录最多 4096 字符、有效期 14 天。不得含令牌、权限、商品文案、自由聊天、凭证或新计算的摘要。
- 不在本批引入服务端草稿事务新架构或手工输入 operation 的恢复后门。

## 行为和信任边界

1. 只在不可恢复会话失效时保留有效的原续接元信息；认证凭证、权限和受保护页面内存仍正常清除。
2. 同账号新认证 `/me` 和当前店铺授权就绪后，按完整 project 三元组把原反馈接到已从后端恢复的商品草稿。不得按邮件/账号提示或缓存权限提前恢复。
3. 当前草稿与原摘要不一致时仍拒绝重新发送；结果核对、原签名和云端检查点 CAS 规则保持不变。不存在原证据时不能补签。
4. 普通刷新、重复 401、重新验证身份时暂时失败、恢复途中写缓存不得意外覆盖尚待恢复的元信息，其他商品的正常快照仍可写入；容量与有效期有界。损坏、过期、错作用域及存储失败保守拒绝。缺失原请求摘要字段不能降级为旧版恢复许可，损坏摘要保持无效，不补签。
5. 显式退出/账户清除仍清除记录，换账号不读取或显示其他账号数据。
6. 恢复本身不得发起生成 POST、素材调用、资金或 eBay 写入；保留用户主动点击核对/继续的边界。
7. 最近任务若已无该操作的恢复信息，不再宣称页面存在生成反馈；准确说明旧草稿保留、未自动重试，不能拿其他历史任务替代本次操作。

## 验证

先用真实失效处理与恢复函数构建本地 RED，再逐项修复：同身份恢复原操作；未认证不显示；跨 user/company/store/project 拒绝；显式退出删除；重复失效与缓存写入不丢记录；无自由文本/凭证；摘要损坏不补签；恢复零生成调用。复用现有原操作续接和检查点专项，保留原安全断言。
