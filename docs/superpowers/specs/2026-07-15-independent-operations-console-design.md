# 捷境独立运营后台设计

## 1. 目标

为捷境建立一个与商家工作台分离的内部运营后台，入口为 `ops.jiejing.shop`。后台服务于主理人及未来的财务、客服、运营人员，用真实数据回答以下问题：

- 有多少访客、注册商家、活跃商家和付费商家？
- 从访问定价页到注册、试用、付费的转化在哪里流失？
- 订阅、素材额度等捷境收入是多少，退款和支付异常是什么状态？
- 商家自带模型和捷境试用模型分别消耗了多少 token？
- 图片、视频和其他供应商能力花费多少，成本覆盖是否完整？
- AI CEO、Listing、批量铺货、素材工坊和决策中心是否稳定？
- 当前有哪些严重告警、失败任务、安全事件和需要人工处理的事项？

后台不是商家产品功能，不出现在商家导航、官网导航或公开站点地图中。

## 2. 非目标

- 不把 eBay 店铺销售额当成捷境收入。
- 不把供应商估算成本伪装成已对账成本。
- 不在后台展示或存储模型 key、支付密钥、eBay token、refresh token、原始 provider 响应、完整提示词或模型回复。
- 不提供绕过确认中心的真实付款、退款、eBay 发布、改价、库存、广告、采购或政策修改入口。
- 不在生产后台使用虚构业务数据；无数据时显示空状态，数据不完整时显示覆盖率和缺口。

## 3. 参考原则

后台采用成熟 SaaS 控制台的共同模式：

- Stripe：总览指标可以下钻到订单、订阅、退款和失败原因，收入与支付状态分开。
- Vercel：可观测性、角色权限和审计日志是独立能力，生产检查有明确门禁。
- Shopify：运营指标和商家业务报告按时间范围、渠道和对象筛选。
- Cloudflare：流量分析与审计日志分离，安全操作保留操作者和时间证据。

捷境不复制这些产品的视觉外观，只采用其信息架构、可追溯性和权限分层原则。

## 4. 信息架构

### 4.1 经营总览

- 今日、7 天、30 天时间范围。
- 访客、注册、活跃商家、付费商家、MRR、实收、退款、贡献毛利状态。
- 转化漏斗：访问 -> 定价页 -> 注册开始 -> 注册完成 -> 试用激活 -> 首次付费。
- 待处理事项：支付异常、退款待审、成本缺口、任务积压、严重告警。

### 4.2 流量与转化

- 唯一访客、会话、页面浏览、定价页浏览和注册转化。
- 页面、日期和事件维度趋势。
- 只存随机标识的 keyed hash、允许列表页面和事件；不存 IP、完整 URL、查询参数、User-Agent 或指纹。

### 4.3 商家与订阅

- 商家列表：脱敏邮箱、注册时间、当前套餐、订阅状态、到期时间、最近活跃时间。
- 套餐分布、试用转付费、流失和到期风险。
- 仅查看权益结果，不展示支付或模型密钥。

### 4.4 交易与退款

- 捷境平台订阅和素材额度订单，而不是商家的 eBay 订单。
- 订单状态、实收金额、退款金额、回调状态、权益发放状态和异常原因代码。
- 退款只允许进入受控审核流程；后台不能直接静默退款。

### 4.5 AI 与素材成本

- 商家 BYOK 与捷境试用模型分开统计请求、输入 token、输出 token 和总 token。
- 图片、视频等素材能力统一按 provider-neutral 资源类型统计，前端不出现供应商品牌。
- 成本状态区分 `actual`、`reconciled`、`configured_estimate` 和 `unavailable`。
- 仅当收入和全部相关成本都有可靠证据时显示贡献毛利；否则显示“数据不完整”及覆盖率。

### 4.6 任务与工作流

- AI CEO、Listing、批量铺货、素材工坊、决策中心的任务量、成功率、失败率、P50/P95 延迟和重试量。
- 下钻只展示脱敏任务引用、模块、状态、错误代码、创建和更新时间，不展示商家内容正文。

### 4.7 系统可靠性

- API、数据库、队列、Worker、支付回调、模型与素材能力的健康状态。
- 当前告警、已确认告警和恢复证据。
- 只读诊断默认开放给内部角色；重跑或维护动作必须单独授权。

### 4.8 安全与审计

- 登录、权限变更、订阅权益变更、退款审核、告警确认和维护命令的审计记录。
- 记录操作者、角色、时间、动作、目标脱敏引用、结果和理由，不记录 secret。
- 支持按日期、动作和结果筛选。

### 4.9 内部设置

- 运营后台角色、告警阈值、成本费率版本和数据保留策略。
- 费率更新必须版本化，只影响新产生的估算；历史已对账成本不可覆盖。

## 5. 三本账

### 5.1 捷境平台收入账

- 订阅订单、素材额度订单和未来明确属于捷境的服务收入。
- 指标：实收、退款、净收入、MRR、活跃订阅和支付成功率。

### 5.2 商家经营数据账

- eBay 等平台的 GMV、订单、广告和退款，只表示商家经营结果。
- 此账与捷境收入完全分离，默认不计入经营总览的收入或毛利。

### 5.3 捷境供应商成本账

- 捷境承担的平台模型、搜索、素材和基础设施成本。
- 商家 BYOK token 只统计使用量，不计为捷境模型成本。

## 6. 核心指标定义

- `unique_visitors`：时间范围内去重的 visitor hash。
- `sessions`：时间范围内去重的 session hash。
- `pricing_views`：定价页允许列表事件数。
- `registrations`：注册完成事件或已创建账号数，以后端账号事实为准。
- `active_merchants`：时间范围内有登录、对话或工作流活动的公司数。
- `active_subscribers`：当前权益处于生效状态的公司数。
- `paid_conversion_rate`：首次成功付款公司数 / 注册完成公司数。
- `mrr_minor`：当前月度订阅标准化后的人民币分值；一次性素材额度不计入 MRR。
- `platform_net_revenue_minor`：实收减已完成退款，不包含商家 GMV。
- `provider_cost_minor`：实际、已对账或明确配置的估算成本之和。
- `contribution_margin_minor`：平台净收入减供应商成本；成本覆盖不完整时不输出确定值。

所有金额以整数 minor units 传输，前端只负责格式化显示。

## 7. 数据接口

### 7.1 总览

- `GET /owner/operations-overview?period_days=7|30|90`
- 返回指标、趋势、漏斗、收入账、成本账、可靠性和数据覆盖状态。

### 7.2 下钻

- `GET /owner/operations/traffic?period_days=&cursor=&limit=`
- `GET /owner/operations/merchants?status=&plan=&cursor=&limit=`
- `GET /owner/operations/transactions?status=&kind=&cursor=&limit=`
- `GET /owner/operations/costs?category=&coverage=&cursor=&limit=`
- `GET /owner/operations/workflows?module=&status=&cursor=&limit=`
- `GET /owner/operations/audit?event=&result=&cursor=&limit=`

所有列表限制最大页大小，游标为不透明值；响应包含 `next_cursor`，不暴露内部自增 ID。

### 7.3 命令

读接口与命令接口分离。任何可能改变资金、权益或外部平台状态的命令必须满足：

1. 查看对象详情和影响范围。
2. 校验角色权限。
3. 填写原因。
4. 重新认证或 MFA。
5. 带幂等键执行。
6. 写入不可变审计记录。

本阶段只实现只读后台和已有的告警确认，不新增真实资金或平台写入命令。

## 8. 身份、会话与权限

- `owner`：全量只读、内部设置、告警确认和未来高风险命令审批。
- `finance`：收入、订单、退款和成本；不能查看商家业务内容或系统密钥。
- `support`：商家账号、订阅状态和工单所需的脱敏状态；不能查看成本或修改资金。
- `operations`：流量、工作流和可靠性；不能查看支付敏感信息。

第一阶段只启用现有 owner 账号，但 API 和前端都按角色保留扩展边界。

运营后台使用独立域名和独立页面。优先采用 Secure、HttpOnly、SameSite=Strict 的后台会话 cookie；在现有 bearer 会话迁移完成前，独立页面只能从同一后端登录并把令牌保存在当前标签页的 `sessionStorage`，不得共享到商家域名、localStorage、URL 或日志。普通商家账号必须返回 403。

## 9. 安全与隐私

- `ops.jiejing.shop` 设置 `noindex,nofollow`，不进入 sitemap。
- 响应启用 CSP、HSTS、`X-Content-Type-Options`、`Referrer-Policy: no-referrer` 和禁止嵌入。
- CORS 只允许运营后台和既有商家域名的明确来源，不使用通配符。
- 登录、总览和下钻接口分别限流；重复失败登录触发审计和告警。
- 脱敏邮箱只显示有限前后缀；visitor/session 只显示聚合，不提供逐个追踪。
- 默认保留聚合指标 13 个月，原始分析事件 90 天，审计日志按合规策略长期保留；清理任务可审计。

## 10. 体验规则

- 桌面端是主要工作环境；平板可完整只读；手机只提供总览、告警和紧急查看。
- 页面采用固定侧栏、紧凑指标、趋势图、表格和下钻抽屉，不使用营销式大 Hero。
- 所有指标都显示时间范围、数据更新时间和覆盖状态。
- 空状态说明“当前没有数据”，不插入示例数字。
- 部分失败时保留已成功区域，并明确显示哪个数据源未更新；不能把整个页面伪装成成功。
- 供应商只以“模型能力”“图片生成”“视频生成”等中性名称出现。

## 11. 部署与域名

- 不购买新域名；在现有 `jiejing.shop` DNS 中增加 `ops` 子域。
- 初期与 `app.jiejing.shop` 使用同一服务器和后端容器，但使用独立 Nginx server block、独立静态入口和独立安全头。
- 后续用户量和合规需求增长时，可以迁移为独立前端和独立后台网关，不改变数据合同。
- DNS 未生效前可通过本地 Host 或 staging 路由验收，但不能宣称线上运营后台已开放。

## 12. 验收与发布门禁

- 未登录访问不返回运营数据。
- 普通商家登录后访问全部内部接口均为 403。
- owner 可以看到真实总览和下钻；无数据时无虚构内容。
- 收入、商家 GMV 和供应商成本不会混算。
- API 和页面中不出现 secret、原始 token、provider 品牌或商家内容正文。
- 游标、页大小、非法筛选、并发刷新、超时和局部失败均有测试。
- 桌面、平板和手机截图检查无重叠、截断或不可读内容。
- secret scan、后端测试、前端浏览器测试、readiness 和线上 smoke 全部通过。
- 真实付款、退款、eBay 写入和素材生成在本次验收中保持关闭。

## 13. 发布顺序

1. 补齐只读聚合与下钻 API。
2. 实现独立运营后台页面和角色拒绝态。
3. 配置独立静态路由、安全头和 DNS 预留。
4. 运行权限、隐私、极端输入、并发和失败恢复测试。
5. 部署到现有服务器并验证；DNS 可用后再公开内部入口。
6. 后续再增加 MFA、高风险命令、告警通知和更细的角色权限。
