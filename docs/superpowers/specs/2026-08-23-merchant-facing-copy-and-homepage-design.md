# 捷境全站商家化文案与首页收敛设计

日期：2026-08-23  
状态：方案 A 与“默认空白工作台”已由用户确认，待书面规格复核

## 1. 决策摘要

捷境采用“全站商家结果导向”方案，而不是只清理公开首页，也不使用运行时字符串替换掩盖旧文案。

- 首页、登录前入口、工作台空状态、客户可见任务结果和风险提示统一面向商家表达。
- 客户进入工作台后默认为空白，不预置“倒流香炉”或其他固定商品；商家提交自己的商品资料后才生成内容。
- 公开首页收敛为 6 个核心板块，只保留一个填充式主按钮“免费生成第一条草稿”。
- 模型 API、BYOK、权限、账单和运行状态等复杂控制项继续留在“设置”或受保护的内部运营页面。
- 客户可见页面不再使用“主理人汇报”“Runtime”“Agent”“packet”“provider”“preflight”“Vault”等内部工程语言。
- “侵权检测通过”“IP 初筛通过”等过度承诺统一收敛为“侵权风险初筛，仍需商家核对”。

本设计不改变既有支付、素材点、免费体验、eBay 写入或确认中心的后端安全边界。

## 2. 商家真实问题与成功标准

### 商家真实问题

当前客户可见页面混合了产品介绍、内部研发进度、技术运行证据和特定店铺商品案例。新商家可能无法快速回答三个问题：捷境能帮我完成什么、我现在该点哪里、系统会不会自动发布或扣费。

### 成功标准

1. 新商家在首屏 10 秒内能理解捷境会把商品资料整理成可核对的 eBay 草稿。
2. 首页只有一个视觉主行动，按钮文案固定为“免费生成第一条草稿”。
3. 未登录和首次登录用户不会看到任何固定商品、旧店铺或个人化经营案例。
4. 所有风险结论明确为初筛或提示，不暗示平台审核、法律审查或零侵权保证。
5. API、权限、账单、密钥和运行状态不会挤占首页或核心经营工作流。
6. 商家可以清楚看见发布、收费、退款和真实店铺写入仍需人工确认。

## 3. 公开首页信息架构

首页保留以下 6 个核心板块。导航和页脚不计入板块数量。

### 3.1 首屏：一句价值主张

- 标题：`把商品资料，变成商家可以核对的 eBay 草稿`
- 说明：上传图片、货源链接或商品资料，捷境协助整理标题、属性、描述与风险疑点；关键操作由商家确认后执行。
- 唯一填充式主按钮：`免费生成第一条草稿`
- 登录入口使用普通文字链接，不与主按钮竞争。
- 首屏不放模型供应商、API 配置、系统百分比或内部架构图。

### 3.2 商家得到什么

展示一份不含具体商品事实的草稿骨架，包括标题建议、属性缺口、描述、利润参考、资料来源与待确认项。骨架只解释结果结构，不伪造真实客户案例或经营成果。

### 3.3 三步开始

1. 提交商品图片、货源链接或文字资料。
2. 核对标题、属性、描述、利润参考和风险初筛。
3. 连接 eBay 后保存为未发布草稿；正式发布仍需商家确认。

### 3.4 信任与安全边界

- 信息建议显示当前资料来源与缺口。
- 统一使用“侵权风险初筛，仍需商家核对”。
- 明确发布、收费、退款、广告、库存及其他真实平台写入需要确认。
- 不使用“检测通过”“已合规”“零风险”等无法证明的完成性结论。

### 3.5 经营阶段与套餐

只呈现三条公开路径：免费体验、有店铺、多店铺。价格、期限、任务额度和套餐素材点必须调用现有套餐合同或同一前端配置源，不在首页另写第二套容易漂移的数字。

素材点权益继续遵循 `2026-08-22-media-points-entitlement-and-quality-design.md`；免费体验与付款路径继续遵循现有已确认规格。本次不重新定义套餐数值。

### 3.6 常见问题与支持

用短问答解释：是否自动发布、是否自动扣费、侵权初筛的边界、什么时候需要连接店铺、在哪里管理套餐和模型设置。该板块不再放第二个填充式主按钮；可使用普通支持链接。

## 4. 默认空白工作台

### 首次进入

- 显示“上传第一份商品资料”。
- 支持图片、货源链接或文字说明。
- 空状态说明“先生成草稿，商家核对后再决定是否连接店铺或执行下一步”。
- 不自动打开旧商品、演示店铺、历史主理人项目或内部任务看板。

### 已有商家数据

- 已有账号继续显示其自身有权限的数据，不清空、不改写、不迁移历史记录。
- 本设计只移除新用户和无数据用户的固定演示种子。
- 历史深链接若指向用户有权限的真实项目，仍正常打开；若不存在，则回到安全空状态。

### 示例策略

客户可见主流程不预置具体 SKU。帮助文档如确需举例，只能使用明确标注为“通用示例”的中性字段骨架，不使用用户店铺商品、私有图片、真实订单号或未经证明的经营结果。

## 5. 全站文案规则

### 应使用的商家语言

| 内部或旧表达 | 客户可见表达 |
| --- | --- |
| 主理人复盘 / 给你汇报 | 经营概览 / 待处理事项 |
| Runtime / Agent 运行 | 服务状态；仅在设置的高级区域出现 |
| 生成 packet / preflight | 准备草稿 / 发布前检查 |
| IP 初筛通过 / 侵权检测通过 | 侵权风险初筛，仍需商家核对 |
| 自动执行完成 | 已生成建议 / 等待商家确认 |
| 模型供应商调用成功 | 内容已生成；技术明细放设置或内部日志 |
| Vault / 密钥边界 | 密钥安全设置；只在设置中心解释 |

### 写作约束

- 先说商家能得到什么，再说需要补什么资料。
- 每个客户页面只突出一个下一步动作。
- 事实不足时写“资料不足”“待核对”，不补造结论。
- 不用只适合开发者或项目主理人的进度语言。
- 不把测试、演练、mock 或本地通过写成正式能力已上线。
- 不承诺销量、利润、平台审核或法律合规结果。

## 6. 页面和权限边界

### 留在核心商家页面

- 商品资料提交与草稿结果。
- 来源、缺口、风险提示和商家确认状态。
- 套餐当前权益的简明摘要。
- 与当前经营任务直接相关的下一步。

### 移到设置中心

- 模型 API 与 BYOK。
- 店铺连接和权限范围。
- 套餐、账单、素材点明细和支付记录。
- 安全设置、登录设备、通知偏好。
- 商家可理解的服务状态与故障提示。

### 仅限内部运营页面

- Runtime、worker、provider、packet、preflight、Vault、队列和部署证据。
- 跨租户运营指标、生产就绪门禁和内部发布检查。
- 这些内容不得因前端路由、空状态或错误回退泄露到普通商家页面。

## 7. 交互与路由

- “免费生成第一条草稿”是首页唯一填充式主按钮。
- 未登录商家点击后进入注册或登录，并保留“免费体验”意图。
- 完成安全验证后进入默认空白工作台，不创建支付订单。
- 付费路径继续在工作台的“设置 -> 套餐与付款”中二次确认金额后发起。
- 设置入口可以从头像菜单或工作台次级导航进入，但不占用首页首屏。
- eBay 保存、发布、收费、退款和其他高风险动作继续经过现有确认边界。

## 8. 实现范围

实施阶段至少覆盖：

1. `index.html`：公开首页结构、CTA、风险文案和套餐入口。
2. `app.html`：登录前入口、首次使用空状态和客户可见静态文案。
3. `app.js`：新用户默认状态、固定商品演示种子、客户可见任务卡与状态映射。
4. `styles.css`：6 板块首页、单主行动层级和移动端适配。
5. 客户可见法律、支持和退款页面：只做术语一致性检查，不扩大政策内容。
6. 设置与内部运营页面：验证复杂信息留在正确权限边界，不为追求“全站统一”删除必要的内部证据。

禁止使用全局运行时字符串替换作为主要实现方式。旧词应从对应的数据源、模板或组件中修正；确需兼容历史记录时，使用显式的展示映射并保留原始审计数据。

## 9. 验收与测试

### 静态合同

- 公开首页恰好只有一个填充式主 CTA，文字为“免费生成第一条草稿”。
- 客户可见入口不含“倒流香炉”、旧店铺名称、主理人汇报或内部运行术语。
- 公开风险提示不含“侵权检测通过”“IP 初筛通过”。
- 首页存在“侵权风险初筛，仍需商家核对”。
- 模型 API、权限和账单配置不出现在首页核心板块。

### 行为合同

- 新账号和无数据账号进入空白工作台。
- 已有账号只看见其有权限的真实数据，历史记录不被空状态覆盖。
- 首页主 CTA 保留免费体验意图并进入正确的注册登录路径。
- 免费体验不会创建支付订单。
- 所有真实 eBay 写入和支付动作继续要求既有确认或后端验签。

### 浏览器验证

- 桌面宽度与移动宽度分别检查首页 6 板块、单主行动、导航和空状态。
- 验证注册、登录、首次进入、已有账号恢复、设置入口和退出登录。
- 检查浏览器控制台错误、页面错误、溢出、遮挡和键盘焦点。
- 验证普通商家无法通过路由直接看到内部运营页面。

### 完成声明

只有本地测试、浏览器回归和线上目标环境核验均通过，才可以说“全站商家化改造已上线”。本地设计或代码完成不能等同于生产已完成。

## 10. 非目标

- 不在本次重构微信支付、素材点计价或模型供应商。
- 不更改已确认的套餐权益数值。
- 不删除历史项目、审计记录或真实商家数据。
- 不触发真实 eBay 发布、退款、广告、采购付款或政策编辑。
- 不把内部运营控制台改成普通商家页面。
- 不用虚假客户案例、虚假销量或虚假“已通过平台审核”增强营销效果。

## 11. 方案取舍

### 采用：方案 A，全站商家结果导向

它同时解决公开获客、首次使用和登录后体验割裂，且把复杂能力保留在设置和内部运营边界内。

### 不采用：方案 B，只改公开首页

虽然速度快，但商家登录后仍会看到固定商品和内部语言，不符合“全站统一”。

### 不采用：方案 C，动态替换旧词

覆盖看似广，实际容易漏词、误替换审计内容，并持续积累维护风险。
