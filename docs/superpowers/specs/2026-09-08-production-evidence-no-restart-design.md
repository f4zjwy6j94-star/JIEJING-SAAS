# 生产证据刷新不重启服务：修缮方案

状态：2026-09-08 用户“同意，继续”已确认本方案，进入本地实现与验证；未授权本批正式部署。旧路径的隔离生命周期诊断已完成，见下文；关联当前执行索引，不替代它。

## 已核实的问题与边界

现有 `jiejing-production-evidence-auto-refresh.sh` 在 COS、CLS 与告警核验成功后，将六项证据更新到宿主私有环境文件，然后依次强制重建 API、Worker。`backup_plan.py` 和 `monitoring.py` 读取的是进程环境，因此宿主文件更新不能自动被原进程读取。重建是旧传输方案的要求，不是云探针本身要求。

已有生产元数据证明一次维护窗口内 API、Worker 身份变化而镜像未变；这说明存在中断风险，不证明全部历史 502 的根因。现有刷新守卫的生命周期测试使用替身，没有证明真实在途请求不中断。`production_evidence_ledger` 只是只读汇总，不是可更新证据存储。

2026-09-08 本地 WSL/Linux 实际服务器类与实际 `/health` handler 隔离对照：成功解析请求后设置仅测试屏障；正常解除屏障返回完整 200，对本次自建进程发送 SIGTERM 则原请求 `RemoteDisconnected`。显式空白安全环境、仅回环，无 provider/生产动作，测试进程均清理。它证明生命周期中断机制，不是完整 Compose 重建复现，也不是新方案 GREEN。直接工具结果 `91459c`，脱敏整理回执位于任务工作区 `output/evidence-maintenance-diagnosis-20260908/lifecycle-mechanism.json`。

本轮不操作 eBay、收费、退款、模型、FAL、用户配额或平台政策；不改变产品结构、套餐和权限；不接触三个用户原有修改文件。尤其不修改当前用户 dirty 的 `readiness.py`。

## 方案比较与推荐

1. **推荐：独立非秘密证据快照，运行时按需读。** 保留现有探针、定时器和锁；不新增服务器或数据库表，避免日常重建。增加一个很小的文件读取与安全验证边界。
2. 延长重启间隔或停止等待时间：不能保证原请求完成，可能让证据先过期，不解决根因。
3. 双实例滚动更新：可以服务正式代码发布，但增加内存、路由和运维复杂度，不是本次低成本证据刷新的最小方案。

## 设计约束

- 专用快照只允许现有六项证据：COS 成功时间、CLS 控制面时间、CLS 摄取通过标志与时间、延迟/费用告警核验时间。拒绝未知字段、重复 JSON 键和非法类型；不含密钥、商家内容、云资源 ID 或业务开关。
- 生产宿主固定目录 `/opt/jiejing-production/runtime-evidence`（root:root、0755），文件 `current.json`（root:root、0644，最多 16 KiB）；容器只读目录为 `/run/jiejing-production-evidence`。文件与父路径不允许符号链接，拒绝组/其他用户可写。内容仅允许固定版本号与六项证据字段；0644 可读的仅是非秘密证据，不用于任何私有 env/凭据文件。
- 由 root 控制的维护流程原子写入独立目录，API/Worker 只读挂载目录而非单文件，避免原子替换后继续看到旧 inode。不挂载整个私有 env 目录，不修改进程全局 `os.environ`。
- 备份/监控构建函数按次读取一个完整快照，在同次构建内复用；继续执行现有过期、未来时间和事实校验，不延长有效期。
- 未启用新模式的旧版本/本地测试保留原 env 读取；一旦明确启用新模式，文件缺失、损坏、符号链接或权限不可信必须失败关闭，不能回落旧 env 得到假绿。
- 保留现有真实探针验证、部署/维护互斥锁、当前发布/镜像与权限校验。维护成功前后 API/Worker 容器身份须保持相同，不再把身份变化当成功条件。
- 保留原 env 证据更新以兼容回滚；仅从已经验证的证据字段生成快照。部分探针失败不生成整轮成功快照、不伪造其他成功时间，旧有效证据按原时效自然到期。
- 双写顺序固定：先完成原 env 的真实证据原子更新和验证，再发布快照。env 或快照任一写入失败都不能报告整轮成功；rename 前失败保留上一完整快照，rename 后目录 fsync 失败可能已可见完整新快照，但不报告成功、不承诺掉电持久性。不回滚已取得的真实 env 成功证据。增加两次写入之间中断的故障注入测试，不能把两个文件宣称为同一原子事务。
- Worker 当前监控主循环没有发现对这六项的直接读取依赖，取消其例行重建不等于证明其所有业务执行具备恰好一次语义；本轮不扩大任务重试或结算重放。

## 首次部署与回滚

必须把首次快照初始化纳入部署前置验证，不能先启用读取模式再留空文件。初始化只能复制现有真实证据，不把部署时间当探针成功时间。初始化失败不得切换候选；过期证据继续由原规则拒绝。

新的文件目录与权限、Compose 只读挂载、候选源码和安装脚本须由现有发布通道核验。回滚恢复原版本/原 env 传输路径，不删除数据库、快照或恢复材料。不允许旧镜像在不支持新读取协议时跳过重建后报告刷新成功。

本方案解决日常证据维护，不宣称正式代码发布也已实现零停机。正式 apply 仍需精确候选通过测试、核包、dry-run 和动作确认。

## 验收边界

1. 本地真实 HTTP 隔离测试：请求已解析、响应尚未发出时，旧生命周期停止使原请求失败；新健康实例不能覆盖此失败。仅进程停止对照须标明不是完整 Compose 实验。
2. 新路径保持原进程与在途请求：原请求完整返回，下一次备份/监控计算看到新合成证据，进程 env 不变。
3. 负例覆盖缺失、半写、非法 schema、重复键、未知字段、过期/未来证据、符号链接/权限错误；不得回落到旧 env 假绿。
4. 真实探针失败短路、部分成功、部署锁竞争、首次迁移、旧版本回滚、资金/eBay开关不变均有本地隔离合同；禁止对生产故意重启做实验。
5. 专项、秘密扫描、语法与新同源完整门禁通过后才准备发布；不复用 3cb50e2 的 227 项结果给新代码背书。

## 自审结论

范围仅动态证据传输，不扩大收费或平台写权限；未用延长时效换取绿灯。首次初始化、失效拒绝和旧版本兼容均为必须验收项。实现时必须固定目录/文件协议并在同一批测试中绑定，不能留下生产临时脚本或平行证据源。
