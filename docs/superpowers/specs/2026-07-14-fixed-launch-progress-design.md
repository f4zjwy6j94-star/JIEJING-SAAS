# 捷境固定上线进度与自主任务队列设计

## 目标

解决上线进度口径随汇报变化的问题。正式公开收费上线进度必须由后端证据计算，不能由人工临时估算；商家前台不展示内部完成度。

## 固定口径

总分固定为 100 分，契约版本固定。六个类别及权重如下：

- 商家产品闭环：20
- 平台运行可靠性：20
- 支付与权益：20
- eBay 生产接入：20
- 安全与合规：10
- 商业上线验收：10

每个类别由固定检查项组成。检查项只有证据通过才得分；增加新功能不能临时扩大分母。实际证据失效时允许分数下降，但必须同时返回退化检查项，禁止只返回一个无法解释的百分比。

## 自主任务队列

未完成检查项按责任边界分为：

- `codex_internal`：代码、测试、监控、备份、浏览器回归和发布证据，Codex 可直接继续。
- `founder_external`：外部平台账号审核、主体资料或控制台批准，需要主理人配合。
- `joint_confirmation`：公开收费、退款、真实 eBay 写入等高风险切换，必须经过确认中心或主理人批准。

后端返回 `next_autonomous_action`，Codex 默认领取最高优先级的 `codex_internal` 项，不等待逐项提醒。

## 支付方向

中国大陆首发以微信支付 Native 为正式收款主路径。Stripe 保留为未来境外扩展能力，不再作为大陆公开上线进度的必选前置条件。

微信支付已经完成的小额实付、签名、回调验签、金额核对和权益发放计入证据；公开收费开关、退款运营验收和主理人批准仍保持未完成，不因技术验收自动开放扣款。

## 边界

- 仅内部管理员可查看固定进度和自主任务队列。
- 不返回 API key、支付密钥、eBay token、原始错误或商家敏感数据。
- 本改造不触发真实收费、退款、eBay OAuth 或平台写入。
- 公共 readiness 继续只陈述可公开事实，不暴露内部执行队列。

## 验证

- 固定权重之和必须始终为 100。
- 相同证据重复计算必须得到相同分数和任务顺序。
- 微信支付受控验收可获得技术完成分，但不能把公开收费批准误判为完成。
- eBay refresh 成功次数为 0 时，eBay 生产接入不能满分。
- 普通商家不能访问内部进度。
- 全量门禁、secret scan、桌面与移动端回归通过后才部署。
