## 问题、选择与非目标

原平板支架一次重写在后端材质质量校验失败，浏览器收到网关 502，未取得完整失败响应。旧稿保留，但页面一直显示结果未知，现有任务卡还错误地要求补充货源资料。中文材质有限别名修复已本地通过，本批合并验证，不重复该生产调用。

选择在现有任务表上增加 Listing 专用操作合同和只读核对入口。不采用清缓存/超时后重新生成；不建立通用任务系统或新数据库。现有 Listing、商品事实、素材、确认中心与套餐结构不变。只改变结果不明时的恢复体验，不放宽事实、图片权利或 eBay 发布边界。

## 操作身份与执行权

- 新页面每次明确生成先保存唯一 `operation_id`；重写须先确认当前云稿已保存，再冻结 base/revision。跨刷新保留完整账号、公司、店铺、项目身份和冻结锚。
- 生成 POST 可携带该编号，旧客户端不携带时兼容既有路径。默认生成和明确重写都可使用编号，不改变默认手改保护。
- 后端用公司/店铺/用户/编号确定唯一任务，原子插入决定执行权。请求规范指纹覆盖模式、完整项目、冻结锚、原编辑字段与商品事实；同编号不同内容返回冲突。
- 重复请求只回读已有结果，不再次调用模型或预留试用。权限、店铺及有界请求验证后立即原子认领，再检查原稿、额度和模型；避免相同请求在原稿检查与取得执行权间交错。明确的保存前阻断先终结自己持有的操作，再返回可重试说明。不存在超时 lease 自动重跑。
- 任务 input 持久化 `listing_generation_operation_v1` 合同，不接受前端自报的阶段、权限、凭据、报告或已成功标记。

## 保存阶段与只读核对

阶段为 `before_model → model_running → saving_report → report_saved`；保存前明确失败为 `failed_before_report`。必须成功持久化 saving_report/保存已尝试，才能进入报告写入。数据库异常不能靠内存默认值推断未保存。

`GET /stores/{store}/listing-drafts/{project}/generation-status` 使用 operation_id 与 source_report_id/candidate_id，必须认证并检查查看权限、完整归属与项目。只读，不产生模型、配额、平台调用或业务记录。

响应白名单包含合同、operation_id、company/store/user、项目身份、冻结锚、task_id、状态、保存阶段、can_retry、可选合法报告、公开失败码/中文原因及安全边界。报告按精确 task_id 查找并验证，真实合法报告优先于任务元数据，不能只看 completed 或输出中的 report_id。

- `report_saved`：接回同一报告；采用仍走原固定 revision CAS，新编辑或冲突不能被覆盖。
- `failed_before_report`：明确终态、未尝试保存、没有矛盾报告证据；保留旧稿，允许下一次商家主动点击创建新编号。
- `running/save_unknown/not_found/conflict`：保留保护。没找到、超时、缺字段或布尔类型不对都不是重试许可。
- 可识别的保存前质量拒绝用严格错误码白名单 422，保留实际原因；存储或网关不确定仍 502，不能仅根据错误码前缀改变状态。

默认生成期间有新编辑时，不自动采用报告。核对到精确已保存报告 N 后，沿用现有云稿冲突卡“保留本机修改并重新保存”：读取当前 N/revision，用原 CAS 保存，再强制回读。只有同一完整作用域、当前 base 与回执都为 N、版本一致、当前/本机/回执的十字段及手改标记一致、没有待保存修改/冲突/存储失败，才结束该次生成反馈；字段不改，报告保留，不追加模型调用。仅找到报告、只选择本地使用云端版本、旧 A 回执或旧幂等写回执均不足以解除；当前读/写句柄在已接受回读时仍可能存在，不能误当结果未知。此项来自234门禁中真实DOM/HTTP路由替身的RED，修的是已批准“新编辑不丢且能继续”的终态缺口，不新增业务接口或确认规则。

## 页面与旧记录

原反馈区域增加“核对本次结果”，显示核对中/已生成/未通过检查/尚未确认。不增独立运行记录导航，不重建商品。最近任务错误原因不可统一指向补货源。

旧 unknown 无编号或持久阶段，不凭最新任务或日期相近自动认领。商家明确选择同项目失败任务后，核对完整归属、历史 revision/base、十字段及手改标记、事实包、唯一不可覆盖的模型调用账本。已审计旧 writer 在报告保存前必先提交同一唯一键的 model_completed，真正 failed 账本不能覆盖它；只有该 failed 证据与任务一致、无报告且无其它未终结或保存未知任务，才证明可主动重试。合法已保存报告按精确任务接回；证据不足保留旧稿。兼容出口有独立反例验证，不伪造历史 phase 或修改旧记录。该限制不得被“流程通过”声明隐藏。

### 商家入口与状态

现有结果区域在精确核对到 `not_found` 后提供“继续本次生成”。页面说明先核对同一次操作，不另建任务；不会自动点击或后台轮询重试。`not_found` 的完整公司/用户/店铺/三字段项目身份及 operation 必须相同，报告为空、can_retry=false、模式及A/R为空、保存/模型/用量阶段为空、安全标记为false。它仅说明此次读取未见任务，不证明从未有晚到请求，不允许创建新编号。

点击继续时重新GET核对；若已运行、成功、明确失败或保存未知，沿现有核对/接回处理，不提交新的生成。只有再次精确not_found及下述原请求校验均通过，才向原POST发送同一operation。POST之后通过现有精确结果读取/采用合同收口，不复制一套报告采用逻辑。

### 原请求与数据保护

新操作在第一次POST之前冻结完整wire请求常量，并持久保存其canonical SHA256请求签名，覆盖模式、完整操作/项目身份、A/R、原商品packet、原模式实际发送的字段及merchant_edited_fields；与已有覆盖十字段/facts/prefill的input_signature一起回读验证后才发送。default保留既有六个建议字段wire，rewrite保留十字段wire，不借恢复修改默认生成语义。请求签名只保存摘要，不重复保存可能包含商家敏感文本的完整请求。续接使用同一构造器从仍一致的本机草稿组装请求，必须匹配原请求签名及原输入签名；发送的就是已核对的常量。不得在恢复时补签、重新capture商品事实、自动flush、借新revision或从后端normalized报告反推原wire请求。

旧操作没有完整请求签名时，仅rewrite允许兼容：原input_signature仍有效，且新认证读取的云端基准为原A、revision为原R，检查点十字段与编辑标记必须逐项等于当前稿。该不可变A/R证据补足旧input_signature未包含marks的部分。旧default没有A/R及原完整请求签名时继续保护，不能事后制造证明。新default有原完整签名且当前数据一致时可按同编号续接。

请求签名的本机证明元数据另外覆盖完整十字段允许集的merchant_edited_fields；default原wire只携带六字段对应marks，不改wire，也不能因此漏掉price/images/logistics/risk_notes的仅编辑标记变化。首次和续接使用同一严格JSON构造器生成签名输入；既有input_signature格式保持兼容。

fresh检查点读取仅验证，不调用会注入报告/采用云稿/清理pending或排队写入的hydrate流程。新default仍使用协议A/R=null，续接要求存在真实检查点且十字段/marks与原输入一致；空检查点不能臆造已保存证明。本次检查短生命周期内固定当前cloud base/revision，观察到版本或编辑变化即停，但不把该临时R写入default请求或持久签名。default没有后端revision CAS，不能宣称读取后所有未观测云写都被原子阻断；rewrite才保留原A/R的后端预检及采用CAS。只发生过revision递增而当前内容完全一致，不等于default原wire请求发生变化。

所有路径保留未保存事实、dirty/pending/conflict/write/read/storage错误检查；每个异步点之后再次检查完整scope、epoch、同operation及新编辑。同步singleflight覆盖连点；刷新后必须重新认证核对，不能直接信任本机“可继续”标记。请求到达后仍由既有原子claim及完整fingerprint裁决，晚到原请求、另一页面或相同编号竞争不能新增第二次模型/额度执行；真实源数据变化仍由既有后端预检拒绝。

### 有界验收

先从真实页面请求在登记前中断的场景建立RED，再按原编号显式续接到真实本地API、保存并刷新读取。随后覆盖晚到原请求、双击/双页竞争、同编号更改字段/marks、GET或hash等待期间编辑/换scope、云端A/R变化、旧default缺凭据及新default刷新续接。只使用loopback测试数据库和外部模型替身，不故意重复生产调用。完成标准为同一次执行可继续、原稿不丢、真实冲突不被清除、已有结果不再次生成；不是允许一切not_found自动重试。

## 验证与完成标准

采用 TDD 垂直小步：正常生成编号回读；同编号并发/重放一次执行；内容冲突；质量失败；保存提交未知；报告已存而响应/元数据丢失；跨租户/店铺/用户/项目；刷新/双击/新编辑/迟到回包；旧多条相似任务不自动匹配。仅本地数据库和外部模型替身，不用真实付费调用故意造错。

完成后合并已有材质补丁，专项与真实 DOM 验证、独立审查、同源新门禁、生产 dry-run、已批准范围部署、独立公共健康/隔离/资产读回，再通过 SaaS 原平板项目续跑。网站在线、私测、公开收费、真实平台写入、原商品流程分别报告，不因测试通过宣称真实发布成功。
