# 捷境 SaaS 任务拆分与市场数据包规则

更新日期：2026-05-12

## 1. 这次暴露的问题

Hermes CEO 按 SaaS 流程调度市场经理时，第一轮市场经理任务 300 秒超时。原因不是业务方向错，而是任务颗粒太大：一个岗位同时承担候选发现、外部数据采集、完整报告、来源标注和 CEO 可读汇总。

第二轮拆小后成功，但为了避免超时，没有实时跑完整 eBay/API/网页采集，只能输出“AI 推断 + 模式识别”的初筛报告。

这说明：正式 SaaS 不能让岗位边查、边算、边写长报告。必须先形成数据包，再写报告。

## 2. 昨天已经解决了什么

昨天已经修掉一个执行 bug：

- 市场经理曾调用不存在的 `web_search` 工具。
- 已新增只读 eBay 市场探针：`/home/hermes/.hermes/scripts/ebay_market_probe.py`
- 已新增搜索引擎公开网页探针：`/home/hermes/.hermes/scripts/web_search_probe.py`
- 已新增公开页面读取探针：`/home/hermes/.hermes/scripts/public_page_probe.js`
- 市场经理技能已要求：工具失败要标注失败，不得假装查到。

今天新增的是“统一数据包入口”：

- `/home/hermes/.hermes/scripts/jiejing_market_data_packet.py`

它会先跑 eBay 官方数据和搜索引擎公开数据，再输出统一 source health。

## 3. 新的固定流程

以后市场阶段必须这样走：

1. AI CEO 接目标。
2. CEO 先建数据采集任务。
3. 系统生成市场数据包。
4. 市场经理只基于数据包和允许的补充资料写报告。
5. CEO 检查报告级别和数据缺口。
6. 商家决定是否进入产品经理。

不能再让市场经理一次性处理完整链路。

## 4. 报告分级

### 初筛报告

数据来源：AI 推断、有限公开信息、少量样本。

用途：判断是否值得继续看。

限制：不能进入发布确认，不能作为采购和定价依据。

### 数据增强报告

数据来源：eBay 官方 API、搜索引擎、公开页面或商家提供资料中至少有一类成功。

用途：可以进入产品经理草稿，生成刊登字段和供应商提问清单。

限制：供应商资料、重量、尺寸、包装和真实采购价没补齐前，不能发布。

### 发布前报告

数据来源：eBay 类目/政策/店铺数据、供应商资料、重量尺寸、真实成本、素材和确认边界已补齐。

用途：可以进入确认中心，等待商家确认是否发布。

限制：仍不能绕过确认中心真实发布、付款、退款、广告或改价。

## 5. SaaS 后端任务拆分

| 阶段 | 任务 | 输出 |
| --- | --- | --- |
| 1 | market.data_packet | 数据源状态、eBay API 摘要、搜索结果、缺口 |
| 2 | market.screen_candidates | 候选品和排除理由 |
| 3 | market.report.one_product | 市场经理报告 |
| 4 | ceo.review_market_report | 报告级别、可信度、是否进入产品经理 |
| 5 | source.collect_supplier_facts | 1688 链接、价格、尺寸、重量、发货地、认证 |
| 6 | listing.ebay_fields | eBay 固定字段和类目动态字段 |
| 7 | media.brief | 图片、详情页、视频脚本需求 |
| 8 | finance.margin | 利润和履约测算 |
| 9 | confirmation.package | 发布前确认单 |

## 6. UI 必须显示

市场报告旁边必须显示来源状态：

- eBay 官方 API：成功 / 失败 / 未授权
- 搜索引擎：成功 / 缺 key / 失败
- 公开页面：成功 / 403 / 验证码 / 未跑
- 1688 货源：已提供 / 未提供 / 需 API / 需截图
- 报告等级：初筛 / 数据增强 / 发布前
- 失败处理：超时 / 已重试 / 等待补资料

商家看到的不是技术日志，而是：

“这份报告能用到哪一步，还缺什么，下一步要不要继续。”

## 7. 当前验证

已验证 `jiejing_market_data_packet.py` 可以成功跑：

- eBay 官方 API：成功
- 搜索引擎公开网页：成功
- 公开页面读取：未跑，仅针对明确 URL 使用
- 1688 货源：未提供，需要商家链接、截图、表格或授权 API

以 `silicone stretch lids / reusable food covers` 为例，eBay Browse API 返回有效市场信号，说明数据增强报告是可行的。

## 8. 结论

超时问题可以解决。正确方案是任务拆分、数据包前置、来源状态可视化、失败重试和报告分级。

没有真实数据时不能硬装成真实调研；有 eBay 官方 API 和公开搜索时，必须使用数据包补强报告。正式发布前，仍要补供应商资料、类目字段、店铺政策、重量尺寸、成本和确认中心。

## 9. 2026-05-13 固化后的岗位闭环

以后 Hermes 和 SaaS 都按同一条链路跑，不再临时拼：

| 顺序 | 阶段 | 主责 | 必须输出 | 失败/缺口处理 |
| --- | --- | --- | --- | --- |
| 1 | AI CEO 接目标 | CEO | 商家目标、风险边界、任务拆分 | 目标不清时先问 1-3 个问题 |
| 2 | 市场数据包 | 系统/工具 | eBay 数据、搜索结果、公开页面状态、来源健康 | 工具失败要标记失败，不得假装查到 |
| 3 | 市场经理报告 | 市场经理 | 用户画像、价格带、竞品痛点、搜索词、机会判断 | 数据不足则降级为初筛报告 |
| 4 | 货源与财务预审 | 财务/供应链 | 采购价、重量、尺寸、发货地、初步利润、是否值得继续 | 缺资料只做草稿，不进入发布 |
| 5 | 产品经理刊登资料 | 产品经理 | eBay 标题、类目、商品参数、价格库存、描述、待补资料 | 类目/参数待校验时标黄 |
| 6 | 素材工坊 | 素材岗位 | 主图、场景图、详情页、尺寸图、视频脚本 | 图片与实物不一致时停住 |
| 7 | 客服学习包 | 客服 | 商品档案、FAQ、自动回复范围、人工接管红线 | 未学习前只能保守草稿 |
| 8 | 财务履约复核 | 财务/履约 | 利润、运费、平台费、订阅费、退货预留、红黄绿结论 | 红灯直接锁发布 |
| 9 | CEO 确认包 | CEO | 发布前摘要、风险、可确认动作、执行边界 | 只把高风险动作送确认中心 |

## 10. 红黄绿发布闸口

### 绿灯

资料、类目、商品参数、图片、价格、库存、店铺政策、利润和履约都达到发布前检查标准。  
仍然必须进入确认中心，不能自动真实发布。

### 黄灯

可以继续做市场报告、刊登草稿、素材和客服档案，但缺少供应商资料、真实重量、包装尺寸、类目校验或店铺规则。  
不能真实发布。

### 红灯

财务、履约、合规、认证、侵权、运费或售后风险不达标。  
AI 只能解释原因、建议暂停或换品，不能诱导商家发布。

不锈钢水杯测试属于红灯样本：毛利偏低、运费占比高、认证/保温/防漏实测缺失，因此应暂停发布。

## 11. 客服学习强制前置

客服不能等出单后再学商品。

产品经理生成刊登资料后，必须同步给客服：

- 商品用途、尺寸、材质、颜色、配件、是否含赠品
- 物流承诺、处理时间、预计时效、不能承诺的话
- 退货、退款、补偿、重发、差评、纠纷的人工接管边界
- 常见买前问题和售后问题

没有客服学习包时，SaaS 只允许生成客服草稿，不允许自动发送。

## 12. 视频素材质量规则

素材工坊不能只交付“图片加口播”的低可信视频。

产品级视频至少要区分三类：

- 商品展示：真实或拟真产品主体、手持/桌面/使用动作、细节镜头。
- 使用场景：买家为什么用、在哪里用、解决什么问题。
- 口播说明：开头钩子、核心卖点、注意事项、字幕和封面。

如果没有真实产品视频，只能标记为“AI 概念视频草稿”，不能当成真实商品展示视频直接用于发布。

## 13. 2026-05-14 闭环测试后的新增规则

理线夹闭环测试后，新增完整经验同步文档：

新增硬规则：

1. 素材工坊拆成 `素材任务包` 和 `素材文件生成` 两步；没有实际文件路径时，不得汇报素材已生成。

4. CEO 接目标时先读取或要求补齐店铺配置和物流报价状态。
5. 市场阶段坚持 `market.data_packet -> market.report` 两步。
6. 系统文件名统一英文数字，中文只做展示标题。
7. 上游关键数据变化时，下游报告必须标记 stale 并刷新。
