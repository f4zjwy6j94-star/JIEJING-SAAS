# 捷境下午任务账本 - 2026-05-27

用途：记录 2026-05-27 下午用户明确交代的连续任务，避免网络中断、上下文压缩或换工具后遗漏。本文档只记录产品任务和复检项，不记录密码、token、eBay refresh token、模型 key 或任何原始密钥。

## 不变边界

- 捷境是 eBay-first AI CEO SaaS，不是通用 ERP、通用 Agent 市场或普通聊天机器人。
- BYOK 模型 key 和 eBay token 只能在后端 secret_ref / Vault / KMS 边界内处理。
- 不重复 eBay OAuth，不要求用户重复配置模型 key。
- 真实发布、采购付款、改价、库存、退款、广告、政策、敏感客服承诺必须进入决策中心。
- 商家界面必须简洁、中文、业务结果导向，不能展示内部 provider 分工解释。

## 下午新增/强调任务

1. AI CEO 对话体验
   - 恢复接近 ChatGPT 网页端的连续对话体验。
   - 最新对话记录和输入框在同一个界面，聊多了向上滚动，不做“收起来的历史对话”。
   - 不显示“调用模型”“后端模型已返回”等技术提示。
   - 普通咨询要像 DeepSeek 一样能自然回答；eBay 经营任务进入工作流；实时数据接联网工具或明确标注来源，不能编。
   - 只有用户明确说“记住这个规则”“以后都按这个做”才写商家规则；真实执行、确认、报告永久入审计和经营记忆。

2. 竞品吸收
   - SellAI Pro：吸收新手 7 步发布引导、模块页输入区/生成按钮/结果区、广告优化入口和 ACOS/预算模拟。
   - AccioWork：吸收一条指令诊断店铺、AI 选品/发品、客户分析与回复话术、主图详情页生成、跨平台资料采集的思路。
   - 悟空：吸收技能库/工作流模板/多角色协作/审批权限的组织方式，但不能把捷境做成泛 Agent 市场。
   - Amazon 经验先作为路线图和跨平台 contract 预留；当前产品仍优先把 eBay 真实闭环做深。

3. 工作流整体联动
   - 改一个细节时，相关模块、测试、文案、工作流、确认边界都要同步演进。
   - 工作流模块必须跟上当前方向：AI CEO 指令 -> 调研/批量/IP -> Listing -> 素材 -> 发布体检 -> 利润 -> 客服订单 -> 决策中心 -> 发布后驾驶舱 -> 审计/记忆。
   - 不能只堆状态，每个业务模块要有明确输入、生成、结果和下一步。

4. 三个用户仍看不懂的页面
   - 决策中心：只处理高风险确认，说明为什么要确认、确认后会发生什么、未确认不会发生什么。
   - 客服与订单：显示真实订单、商品档案、tracking、handling time、客服边界；敏感承诺进决策中心。
   - 设置：集中账号、授权、BYOK、packet、权限、上线、billing、数据源和记忆规则，减少大卡片和状态堆叠。

5. eBay 店铺同步可视化
   - 页面要明确显示店铺名、同步状态、商品数、offer 数、订单数、policy 数、最后同步时间、官方 packet id。
   - 如果没有官方数据，不能假装已同步；要显示缺口和下一步。
   - IP/VeRO 筛查要基于新商品资料、店铺同步商品、来源记录和官方 packet；没有数据就显示“无法扫全店”。

6. 素材工坊
   - 商家只看资产清单和可发布状态，不看“DeepSeek 想图 / FAL 出图”的内部解释。
   - 图片生成、详情图、视频封面、脚本、素材 manifest、授权、尺寸、实物一致性审核都要在素材工坊体现。
   - 生成结果必须回到素材工坊预览和资产清单，发布前进入发布体检和决策中心。

7. AI CEO UI
   - 不要“今天要捷境帮你处理什么？”这句。
   - 界面要宽、大、干净，有连续对话感。
   - 不要小气的窄卡片；输入框固定在底部，内容自然滚动。

8. 实时联网搜索能力
   - AI CEO 要有实时联网搜索能力，输出必须带来源。
   - 搜索结果要区分：官方数据包、订单、财务、公开搜索、模型推理、人工输入。
   - 股票、新闻、汇率、政策变化等实时问题不能用模型硬编。

9. 商业上线缺口
   - 正式收费系统：Stripe/Paddle/Lemon Squeezy、真实 plan、quota、webhook、欠费停用、发票、用量计费。
   - 稳定域名和上线基础设施：正式域名、DNS/TLS、CORS、OAuth callback、隐私政策、服务条款、稳定部署流程。
   - 发布安全系统：发布体检报告覆盖类目、item specifics、图片、VeRO/IP、禁售词、GPSR、business policy、库存位置、卖家额度、预计费用、利润。
   - 真实店铺同步可视化。
   - 发布后驾驶舱：1 小时、24 小时、7 天复盘曝光、点击、收藏、售出、费用、利润、客服风险。
   - 最终商业 smoke：注册、登录、连 eBay、同步、跑品、素材、发布体检、确认、真实发布、审计回流。

10. 增强项
    - 新商品查重，防止旧品旧图重复测试。
    - AI CEO 每条回复附目标、计划、来源、风险、待确认动作、执行结果。
    - 素材工坊资产清单化。
    - 利润大脑。
    - 失败知识库。
    - 商家规则记忆。
    - 可信来源 UI。

11. 首页话术
    - 删除“主页、向导和工作台只讲同一条 AI CEO 经营闭环”这类内部化表达。
    - 删除“不是通用 ERP，也不是通用 Agent 市场...”这种大字反向定位表达。
    - 改成结果导向：从一个商品目标开始，跑完调研、刊登、素材、体检和发布确认。
    - 表达 eBay 做深，再扩展 Amazon。

12. 部署和复检
    - 本地测试通过后重新打 bundle。
    - staging 当前 public 还可能没吃到最新首页文案，必须部署后再查 public `/health`、`/readiness/product-saas` 和首页 marker。
    - SSH 优先 agentuser 通道；如果通道失败，明确报告失败，不假装部署成功。
